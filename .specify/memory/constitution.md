# T3_LWS Constitution

## Core Principles

### I. 구현·수정 후 실행 화면 MP4 기록

Unity 프로젝트에서 기능을 구현하거나 수정한 작업은 변경 결과를 확인할 수 있는
실제 실행 화면을 MP4 영상으로 녹화하여 저장해야 한다(MUST).
사용자가 나중에 결과를 재생하고 피드백할 수 있도록 변경한 기능의 진입·핵심 동작·결과를
확인할 수 있는 구간을 포함해야 한다(MUST).

녹화 대상은 Unity Editor의 Play Mode 또는 실제 빌드 실행 화면이다.
실행하지 않은 목업·설명 이미지·콘솔 로그를 실제 실행 영상으로 대체해서는 안 된다(MUST NOT).
특정 녹화 도구를 강제하지 않으며 실제 재생 가능한 MP4 파일인지 확인해야 한다(MUST).

### II. 녹화 불가 시 대체 시각 자료와 한계 기록

환경이나 도구의 제약으로 MP4 녹화가 불가능하면 실행 화면 스크린샷 등
대체 가능한 시각적 검증 자료를 반드시 저장해야 한다(MUST).
변화 순서가 중요한 기능은 변경 전후 또는 주요 단계별 자료로 확인할 수 있어야 한다(MUST).
텍스트 로그만으로 시각적 검증 자료 의무를 충족했다고 간주해서는 안 된다(MUST NOT).

MP4를 남기지 못한 이유, 사용한 대체 자료, 그 자료만으로 확인할 수 없는 동작을
함께 기록해야 한다(MUST).
Editor·PC에서 확인한 결과와 실제 VR 기기에서 확인한 결과를 구분해야 하며(MUST),
실행하지 않은 환경을 검증 완료로 표시해서는 안 된다(MUST NOT).

실행 자체가 불가능하면 가능한 범위의 실제 Editor 화면 등 시각 자료를 남기고
실행 검증을 수행하지 못했음을 명시해야 한다(MUST).
대체 시각 자료도 확보할 수 없다면 검증 자료 미확보와 원인을 보고하고,
이 원칙을 충족했거나 시각 검증을 완료했다고 선언해서는 안 된다(MUST NOT).

### III. 검증 결과물의 공통 경로 보관 및 완료 보고

영상·스크린샷·동반 검증 기록은 아래 공통 경로에 보관해야 한다(MUST).

`Artifacts/Validation/VisualEvidence/YYYYMMDD-HHmmss-작업명/`

이 경로는 프로젝트 루트 기준이며 기존 `.gitignore`의 `/[Aa]rtifacts/` 규칙을 사용한다.
영상·스크린샷·동반 기록은 로컬 검증 산출물로 보관하며 Git 추적·커밋 대상에
포함해서는 안 된다(MUST NOT). 강제 추가로 제외 규칙을 우회해서는 안 된다(MUST NOT).
Unity Assets 및 제출용 패키지에 검증 원본을 섞지 않는다.

작업 완료 보고에는 사용자가 바로 확인할 수 있도록 실제 저장한 MP4 또는 대체 자료의
프로젝트 상대 경로나 클릭 가능한 파일 링크를 반드시 포함해야 한다(MUST).
폴더 경로만 제시하지 말고 대표 결과물 파일을 직접 가리켜야 한다(MUST).
녹화 대신 대체 자료를 남겼거나 검증하지 못한 환경이 있으면 그 사실도 보고해야 한다(MUST).

## 적용 범위와 저장 규칙

- 이 원칙은 Unity 기능 구현·버그 수정·동작 변경·UI/씬/자원 변경 등 실행 결과에
  영향을 주는 작업에 적용한다. 명세·계획·헌법 등 문서만 수정하는 작업에는
  새 실행 영상이나 스크린샷을 요구하지 않는다.
- 작업별 하위 폴더 이름은 검증 자료 생성 시각과 작업 식별자를 사용한다.
  같은 경로가 이미 존재하면 접미사를 추가하여 기존 결과물을 덮어쓰지 않는다.
- MP4는 `execution.mp4`, 대체 스크린샷은 `01-장면명.png`처럼 순서와 내용이
  식별되는 이름을 사용한다. 여러 영상이 필요하면 번호와 구간 이름을 함께 쓴다.
- 같은 폴더의 `verification.md`에 작업 식별자, 검증 일시, 콘텐츠/씬,
  실행 환경(Editor/PC 빌드/VR 기기와 기기명), 입력 방식, 확인한 동작,
  결과물 파일명, 실제 결과와 미검증 항목을 기록한다.
  대체 자료를 사용했다면 녹화 불가 사유와 검증 한계도 기록한다.
- 검증 도구의 임시 출력 경로가 다르더라도 완료 보고 전 공통 경로에 결과물을 보관한다.
  캡처를 위해 실행 기능이나 교육 흐름을 임의로 바꾸지 않는다.

## 작업 완료 검증 절차

1. 변경한 기능이 드러나는 실행 경로를 수행하고 MP4를 녹화한다.
2. 녹화가 불가능하면 사유를 기록하고 대체 시각 자료를 확보한다.
3. 공통 경로에 파일과 `verification.md`를 저장하고 파일 존재·열람 가능 여부를 확인한다.
   `git check-ignore`와 `git ls-files`로 제외 규칙 적용과 비추적 상태도 확인한다.
4. 자료가 보여 주는 범위와 실제 확인한 결과를 대조한다.
   영상이나 스크린샷의 존재만으로 모든 기능 검증이 성공했다고 간주하지 않는다.
5. 완료 보고에 대표 결과물 파일 경로와 검증 결과·한계를 포함한다.

후속 명세·계획·작업 목록과 완료 검토는 적용 대상 변경에 대해 위 절차와
시각적 검증 자료 확보 여부를 확인해야 한다(MUST).
기존 문서를 일괄 재작성하거나 과거 완료 작업을 소급 녹화할 의무는 이번 채택에 포함하지 않는다.

## Governance

이 헌법은 이번 사용자 요청으로 채택한 시각적 검증과 결과물 보고의 공통 원칙이다.
기존 사용자 지시와 AGENTS.md의 적용 가능한 규칙을 보존하며,
AI가 수정할 수 없는 AGENTS.md를 대신 수정하는 근거로 사용하지 않는다.

원칙의 추가·삭제·의무 변경은 사용자의 명시적 요청 또는 동의를 근거로 헌법에 반영한다.
개정 시 변경 이유와 영향을 검토하고 버전 및 최종 개정일을 갱신한다.
버전은 의미적 버전 규칙을 따른다. 기존 의무와 호환되지 않는 삭제·재정의는 MAJOR,
원칙 추가나 실질적 의무 확장은 MINOR, 의무를 바꾸지 않는 설명·오탈자 수정은 PATCH다.
최초 버전 1.0.0은 2026-11-11 채택했다. 이번 1.1.0은 검증 자료의 Git 비추적
보관 의무를 추가하고 저장 경로를 교정한 MINOR 개정이다.

계획 및 작업 완료 시 준수 여부를 확인하고 충족하지 못한 항목과 사유를 보고한다.
명세·템플릿·명령 파일은 이 개정에서 수정하지 않는다.
