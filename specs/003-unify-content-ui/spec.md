# Feature Specification: 콘텐츠 공통 UI 통일

**Feature Branch**: 기존 `main` 유지 (이번 명세 작성에서 브랜치 생성 없음)

**Feature Directory**: `specs/003-unify-content-ui`

**Created**: 2026-11-11

**Status**: Draft

**Input**: 사용자 대화: 안내창과 버튼을 콘텐츠마다 새로 만들지 않고 공통으로 사용하며 콘텐츠별 내용과 동작을 연결하고 싶다. ‘화재 사실 알리기’ UI가 상대적으로 낫지만 작업 중 이상하게 바뀔까 걱정된다. 현재 UI와 문서가 다르면 `design.md`에 맞춰 수정하는 방식을 선택했다.

## Clarifications

### Session 2026-11-11

- Q: 안내 대사를 짧게 다듬을 때, 기준으로 삼은 ‘화재 사실 알리기’의 대사도 수정할까요? → A: ‘화재 사실 알리기’의 기존 대사는 유지하고, 다른 콘텐츠의 긴 안내를 그 수준에 맞춰 다듬는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 문서에 맞는 일관된 화면으로 체험하기 (Priority: P1)

체험자는 콘텐츠가 바뀌어도 같은 역할의 안내창과 버튼을 같은 디자인과 조작 방식으로 사용한다. 제작자는 임의의 새 디자인 대신 문서 기준으로 화면을 검토한다.

**Why this priority**: UI 통일 과정에서 현재보다 디자인이 나빠지거나 문서 기준을 벗어나는 것이 사용자의 핵심 우려다.

**Independent Test**: ‘화재 사실 알리기’의 안내·선택·다음 화면을 변경 전후로 비교하고 `design.md`의 관련 규칙과 대조한다.

**Acceptance Scenarios**:

1. **Given** 기존 화면과 `design.md` v0.1.1이 있을 때, **When** 공통 화면을 검토하면, **Then** 폰트·색상·글자 위계·여백·모서리·버튼 상태·읽는 거리·배치의 문서 적합 여부와 변경 근거를 확인할 수 있다.
2. **Given** 두 콘텐츠에 같은 역할의 안내와 선택 화면이 있을 때, **When** 콘텐츠를 바꾸면, **Then** 내용과 행동은 달라도 공통 디자인과 선택 방식은 유지된다.
3. **Given** 기본 또는 150% 글자 설정일 때, **When** 긴 한국어 안내와 선택지를 표시하면, **Then** 필수 문구가 잘리거나 겹치지 않고 축소·말줄임으로 숨겨지지 않는다.

---

### User Story 2 - 화면을 다시 만들지 않고 내용과 행동 연결하기 (Priority: P1)

콘텐츠 제작자는 같은 형태의 안내창과 버튼을 재사용하고, 각 콘텐츠의 안내·선택지와 선택 후 행동을 별도로 연결한다.

**Why this priority**: 콘텐츠마다 UI를 반복 제작하고 같은 기능의 모양이 달라지는 문제를 해결한다.

**Independent Test**: 기존 두 콘텐츠의 안내·선택·다음·준비 완료를 공통 화면으로 표현하고 문구 변경과 행동 실행을 각각 확인한다.

**Acceptance Scenarios**:

1. **Given** ‘화재 사실 알리기’를 실행 중일 때, **When** 행동 선택과 다음 화면을 사용하면, **Then** 기존 선택지와 진행 시점이 유지되고 기존 행동이 선택 한 번에 한 번만 실행된다.
2. **Given** ‘연기 속에서 자세 낮추기’를 실행 중일 때, **When** 준비 완료를 선택하면, **Then** 기존 준비·원리 관찰·자세 연습 순서로 진행하며 연습 중 새 버튼 조작이 추가되지 않는다.
3. **Given** 두 콘텐츠가 같은 역할의 화면을 사용할 때, **When** 한 콘텐츠의 안내 문구를 바꾸면, **Then** 다른 콘텐츠의 문구나 공통 디자인은 바뀌지 않는다.
4. **Given** 공통 버튼 표현을 문서에 맞게 조정했을 때, **When** 두 콘텐츠에서 확인하면, **Then** 각 콘텐츠의 화면을 따로 고치지 않아도 동일한 조정이 반영된다.
5. **Given** ‘화재 사실 알리기’의 기존 대사는 유지할 때, **When** 다른 콘텐츠의 긴 가이드 대사와 자막을 다듬으면, **Then** 그 안내 수준에 맞춰 지금 할 행동과 필요한 이유를 짧고 간결하게 전달하고 긴 설명을 한꺼번에 제시하지 않는다. 필수 안전 조건과 교육 의미는 유지한다.

---

### User Story 3 - 전환과 중단 뒤에도 현재 체험만 조작하기 (Priority: P2)

체험자는 콘텐츠 변경·일시정지·재시작·복귀 후 현재 체험의 안내와 버튼만 사용한다.

**Why this priority**: 공유 화면에 이전 체험의 내용이나 행동 연결이 남으면 잘못된 진행이 발생한다.

**Independent Test**: 메뉴 → 화재 알리기 → 메뉴 → 자세 연습 → 메뉴 → 화재 알리기 전환과 각 콘텐츠의 일시정지·취소·재개·재시작을 확인한다.

**Acceptance Scenarios**:

1. **Given** 다른 콘텐츠로 전환했을 때, **When** 안내와 선택지가 나타나면, **Then** 이전 콘텐츠의 문구·선택지·선택 동작·진행 피드백이 남지 않는다.
2. **Given** 확인창이 열려 있을 때, **When** 뒤쪽 버튼이나 공간 물체를 선택하면, **Then** 실행되지 않으며 취소 후 기존 체험 상태로 돌아간다.
3. **Given** 안내 도중 일시정지했을 때, **When** 계속하기를 선택하면, **Then** 기존 음성·자막·진행을 이어가고 안내나 행동이 중복 실행되지 않는다.

### Edge Cases

- 선택지가 없는 안내, 하나의 준비/다음 버튼, 여러 행동 선택지를 구분하고 빈 버튼을 표시하지 않는다.
- 버튼을 누른 채 화면이 전환되어도 새 화면의 행동을 이어서 실행하지 않는다.
- 긴 한국어와 150% 확대에서도 필수 문구와 행동을 모두 확인할 수 있어야 한다.
- 안내를 줄이면서 필수 안전 조건이나 체험의 한계가 빠지지 않아야 한다. 필요한 설명이 길면 현재 단계에 필요한 내용으로 나누되 새 교육 단계나 추가 조작을 강제하지 않는다.
- 자막을 꺼도 필수 조작·추적 불가·구성 오류 안내와 메뉴 복귀 경로는 제공한다.
- 자세 연습 중 서거나 숙여도 안내와 메뉴를 읽고 선택할 수 있어야 하며 카메라를 강제로 움직이지 않는다.
- 재시작·복귀·추적 복구 시 이전 선택이나 완료가 새 체험에 전달되지 않는다.
- 필수 내용이나 행동 연결이 없으면 정상 체험이나 완료로 가장하지 않고 오류 안내와 복귀 경로를 제공한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 안내·자막·행동 선택·다음·준비 완료 중 같은 역할의 화면과 버튼은 공통으로 재사용해야 한다. 문구 차이만을 이유로 동일 기능의 UI를 콘텐츠마다 별도 제작·관리하지 않아야 한다.
- **FR-002**: 콘텐츠별 안내·음성·선택지·상태 문구와 선택 후 행동은 공통 화면의 모양과 분리하여 연결할 수 있어야 한다. 체험의 진행과 판단은 기존 콘텐츠별 규칙을 유지해야 한다.
- **FR-003**: `design.md` v0.1.1의 사용자 요구·확정 폰트·이 프로젝트 유지 조건을 준수하고 관련 제안 표준의 색상·크기·여백·모서리·상태·공간 배치를 이번 프로젝트의 적용 기준으로 사용해야 한다. 다른 팀 프로젝트의 합의 완료로 기록하지 않아야 한다.
- **FR-004**: ‘화재 사실 알리기’의 변경 전 화면을 비교 기준으로 확보하고, 변경 항목과 문서의 해당 근거를 제시해야 한다. 기존 화면과 문서가 다르면 문서 기준을 적용해야 한다. 문서에 없는 디자인 변경은 별도 제안으로 구분하고 사용자 동의 없이 확정하지 않아야 한다.
- **FR-005**: 기존 대본의 교육 의미·필수 안전 조건·행동 선택·외치기와 비상벨 체험 순서 및 자세 연습의 준비·관찰·실제 숙임·자동 인정·한계 안내를 유지해야 한다. FR-013에 따른 대사 간결화는 허용하되 UI 공통화나 문구 정리 때문에 교육 단계나 조작을 추가하지 않아야 한다.
- **FR-006**: 현재 콘텐츠와 단계에 필요한 안내와 버튼만 표시해야 한다. 전환·재시작·종료 시 이전 내용과 선택 동작을 제거하고 한 번의 새 선택으로 현재 행동을 한 번만 실행해야 한다.
- **FR-007**: 기존 콘텐츠 선택·설정·일시정지·확인·결과 기능을 유지해야 한다. 확인창은 뒤쪽 UI와 공간 입력을 차단하고 계속하기/취소를 기본 선택으로 제공해야 한다.
- **FR-008**: 기존 음성·자막·진행의 동기화와 중단·재개 동작을 유지하고 자막 설정과 별개로 필수 조작·오류·추적 상태를 표시해야 한다.
- **FR-009**: 기본 및 150% 글자 설정에서 필수 한국어의 누락·잘림·겹침을 방지해야 한다. 긴 내용은 영역 확장이나 내용 분할로 표현하고 필수 문구를 임의 축소·생략하지 않아야 한다.
- **FR-010**: 이동·텔레포트·고개 회전 후 읽기·조작이 가능한 기존 UI 동작과 자세 연습의 서기/숙이기 접근성을 유지해야 한다. 물리 비상벨·라벨·안전 표지의 위치와 식별성을 유지하며 공통 화면으로 대체하지 않아야 한다.
- **FR-011**: 필수 내용이나 행동 연결 누락으로 진행할 수 없으면 완료 처리하지 않고 오류 안내와 콘텐츠 선택으로 돌아갈 방법을 제공해야 한다.
- **FR-012**: 검토 자료에는 문서 버전·변경 전후 화면·문서 대비 차이와 이유·검증 환경과 결과를 기록해야 한다. PC와 실제 VR 기기 검증을 구분하고 미실시 기기 검증을 완료로 표시하지 않아야 한다.
- **FR-013**: ‘화재 사실 알리기’의 기존 가이드 대사와 자막 문구는 유지하고 길이와 설명 방식의 비교 기준으로 사용해야 한다. 다른 콘텐츠의 긴 안내는 그 수준에 맞춰 짧고 간결하게 다듬어야 한다. 한 번에 지금 할 행동과 필요한 이유에 집중하고 장황한 설명과 불필요한 반복을 줄여야 한다. 필수 교육 의미·안전 조건·체험의 한계는 생략하지 않으며 음성과 자막의 내용을 일치시켜야 한다. 기존 문구를 유지하면서 표시상 줄바꿈·자막 구간을 조정하는 것은 가능하다. 여기서 가이드 스크립트는 안내 대본이며 코드 길이를 뜻하지 않는다.
- **FR-014**: 구현·수정 후 변경 기능의 진입·핵심 동작·결과를 확인할 수 있는 실제 실행 화면을 MP4로 저장해야 한다. 녹화가 불가능하면 스크린샷 등 대체 시각 자료와 녹화 불가 사유·검증 한계를 남겨야 한다. 자료와 `verification.md`는 헌법의 공통 경로 `Artifacts/Validation/VisualEvidence/YYYYMMDD-HHmmss-작업명/`에 저장하고 완료 보고에 대표 파일의 실제 경로를 포함해야 한다. 시각 자료를 확보하지 못하면 해당 의무 미충족을 명시하며 검증 완료로 선언하지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **공통 화면**: 같은 역할의 표시와 조작을 제공하는 재사용 단위. 공통 디자인을 따르며 특정 콘텐츠의 대사나 행동 자체를 소유하지 않는다.
- **콘텐츠별 표시 내용**: 콘텐츠와 단계별 안내·음성·선택지·상태 문구. 다른 콘텐츠와 독립적으로 변경한다.
- **콘텐츠 행동 연결**: 사용자의 선택을 현재 콘텐츠의 행동으로 전달하는 관계. 전환 후 이전 연결이 남지 않는다.
- **디자인 대조 기록**: 변경 전후 화면·문서 규칙·차이의 처리 근거·검증 환경 및 결과를 묶은 검토 자료.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 두 콘텐츠의 같은 역할의 안내와 버튼을 공통으로 관리하며, 문구 차이만으로 별도 화면을 관리하는 사례가 0건이다. 공통 버튼 표현 변경 한 번이 두 콘텐츠에 함께 반영된다.
- **SC-002**: 변경한 공통 화면의 모든 시각 항목에 문서 적합 여부와 변경 근거가 있고, 근거 또는 사용자 동의 없는 디자인 변경은 0건이다.
- **SC-003**: 두 콘텐츠의 시작부터 완료·복귀까지 기존 행동과 순서를 모두 유지하고, 추가로 강제된 교육 단계나 조작은 0건이다.
- **SC-004**: 두 콘텐츠의 안내·선택·메뉴·결과 화면에서 기본/150% 한국어 필수 문구의 누락·잘림·겹침이 0건이다.
- **SC-005**: 두 콘텐츠 왕복 전환과 각각의 일시정지·취소·재개·재시작에서 이전 내용 노출·잘못된 행동 연결·중복 실행·뒤쪽 입력 실행이 각각 0건이다.
- **SC-006**: PC와 Quest 2의 결과를 분리해 기록하고, Quest 2에서 두 콘텐츠의 안내 읽기·선택·완료·복귀 및 자세 연습의 서기/숙이기 중 메뉴 접근을 확인한다. 미실시 항목은 미검증으로 남긴다.
- **SC-007**: ‘화재 사실 알리기’의 기존 가이드 대사와 자막 문구 변경은 0건이다. 다른 콘텐츠의 모든 가이드 대사에 대해 기존 ‘화재 사실 알리기’ 안내와의 간결성 비교 및 변경 전후 의미 검토 기록을 제공한다. 다듬은 안내는 현재 행동과 필요한 이유에 집중하며, 필수 교육 의미·안전 조건·한계 안내 누락과 음성·자막 내용 불일치는 각각 0건이다.

- **SC-008**: 구현·수정 결과에 재생 가능한 MP4 또는 열람 가능한 대체 시각 자료와 `verification.md`가 공통 경로에 존재하고, 완료 보고에서 대표 파일에 직접 접근할 수 있다. 녹화 불가 사유·검증 한계·환경별 미검증 항목이 누락 없이 기록된다. 자료 자체를 확보하지 못한 경우 이 기준은 미충족으로 남긴다. 문서만 수정하는 작업은 녹화 대상에서 제외한다.

## Assumptions

### 사용자 확정 사항

- 공통 안내창과 버튼을 재사용하고 콘텐츠별 내용과 동작을 연결한다.
- 가이드 안내 대사·자막은 현재 ‘화재 사실 알리기’처럼 짧고 간결하게 하고 지금 해야 할 행동과 필요한 이유에 집중한다. 코드 길이에 대한 요구가 아니다. 2026-11-11 사용자 확인 및 명세 반영 요청.
- ‘화재 사실 알리기’의 기존 대사·자막 문구는 유지하고, 다른 콘텐츠의 긴 안내만 그 수준에 맞춰 다듬는다. 2026-11-11 명확화 질문에서 A 선택.
- 디자인이 임의로 달라지는 것을 우려하며 현재 화면과 문서가 다르면 `design.md`에 맞춰 수정하는 방식을 선택했다. 문서의 제안 수치는 이번 프로젝트 적용 기준이며 팀 전체 확정은 아니다.
- 이번 요청은 위 대화를 바탕으로 새 명세를 작성하는 것이다. 계획·구현으로 자동 진행하는 요청으로 해석하지 않는다.

### 범위·의존성 및 작성 시 기본 해석

- 기존 명세가 있는 ‘화재 사실 알리기’와 ‘연기 속에서 자세 낮추기’에 적용한다. 미확정 콘텐츠나 다른 팀 프로젝트를 새로 구현하지 않는다.
- 공통 UI는 같은 기능을 재사용한다는 뜻이다. 모든 역할과 공간 소품을 한 화면으로 합치거나 모든 콘텐츠에 같은 버튼을 강제하지 않는다. 구체적 구성 방식은 후속 계획에서 정한다.
- 기존 메뉴·설정·결과는 재설계를 목적으로 하지 않으며 공통화와 문서 준수에 필요한 범위에서 일관성을 맞춘다.
- 기존 동작은 [화재 알리기 명세](../001-fire-notification/spec.md), [자세 연습 명세](../002-smoke-low-posture/spec.md) 및 관련 계약을 따른다. 변경은 UI 재사용·문서 적용·교육 의미를 보존하는 가이드 대사 간결화에 한정한다.
- 안내 길이에 임의의 글자 수나 초 단위 상한을 새로 확정하지 않는다. 현재 ‘화재 사실 알리기’의 안내를 비교 기준으로 사용한다.
- `design.md` 12.2절의 콘텐츠 1만 구현 대상이라는 과거 상태 설명은 최신 자세 연습 명세의 범위를 취소하지 않는다. 기존 UI 추종 동작은 기존 명세의 후속 승인 사항을 유지한다.
- 제출용 기능과 자원은 기존 `Assets/_02LWS` 작업·내보내기 조건을 유지한다. 새 점수·타이머·평가·저장·이어하기 또는 새 입력 체계는 추가하지 않는다.
- 헌법 v1.1.0(2026-11-11)의 실행 화면 기록·대체 자료·공통 저장·완료 보고 원칙을 적용한다. 과거 작업의 소급 녹화는 요구하지 않는다.
- 검증 영상·스크린샷·동반 기록은 프로젝트 루트의 Git 제외된 `Artifacts/` 아래에 로컬 보관한다. Git 추적·커밋·강제 추가 대상이 아니며 제출용 코드/자원과 구분한다.

### AI 제안 — 미확정

- ‘화재 사실 알리기’의 변경 전후 모습을 먼저 보여주고 사용자가 확인한 뒤 다른 콘텐츠에 적용하는 단계적 검토를 제안했다. 이 절차는 아직 사용자가 명시적으로 승인하지 않았다. 확정 요구는 비교 자료 제공까지이며 적용 순서와 별도 승인 단계는 후속 논의 대상이다.
