# Quickstart validation: 콘텐츠 공통 UI 통일

**현재 상태**: 설계 단계. 아래 도구/프리팹은 구현할 대상이며 아직 실행하거나 구현 완료한 결과가 아니다.

## 준비와 실행

Unity Hub에서 기존 프로젝트를 Unity 6000.3.26f1로 연다. 패키지를 업그레이드하지 않는다. `Assets/_02LWS/Scenes/FireNotification.unity`를 열고 Console 컴파일 오류 0건을 확인한다. 콘텐츠 메뉴 진입 씬도 따로 실행해 실제 씬 연결이 유지되는지 확인한다.

구현할 Editor 메뉴 `LWS/Validation/Shared Experience UI`는 [연결 계약](contracts/shared-experience-ui.md)의 RunAll을 호출한다. 메뉴를 실행해 PASS와 실패 0건을 확인한다. 프로젝트가 다른 Editor에서 열려 있지 않을 때만 다음 batch 대안을 사용한다. 설치 경로는 Hub의 실제 6000.3.26f1 위치로 지정한다.

```powershell
$unityEditor = 'C:/Program Files/Unity/Hub/Editor/6000.3.26f1/Editor/Unity.exe'
& $unityEditor -batchmode -quit -projectPath 'D:/Projects/T3_LWS' -executeMethod LWS.FireNotification.Editor.SharedExperienceUIValidation.RunAll -logFile 'D:/Projects/T3_LWS/Logs/SharedExperienceUIValidation.log'
```

경로가 다르면 Hub에서 확인해 변수만 바꾼다. 설치나 별도 테스트 패키지는 이 가이드의 전제에 포함하지 않는다. 검증 실패 시 출력된 조건을 수정한 후 해당 검증을 재실행한다.

## V1. 기준 확보·디자인·원문 — SC-001/002/004/007

구현 전에 화재 안내/선택/다음/메뉴/결과의 화면과 원문 데이터를 확보한다. 구현 후 기본/150% 화면을 같은 조건으로 비교한다. design.md 5~10절 항목별 적용값·차이·이유를 남긴다. 공통 Theme/버튼 한 항목을 임시로 바꿔 두 콘텐츠에 반영됨을 확인한 뒤 원래 적용값으로 되돌린다. 다른 작업의 변경을 되돌리지 않는다.

필수 문구 잘림·겹침·누락 0건, 같은 대사 이중 표시 0건. 긴 버튼은 전체 문구와 선택 영역이 확보되어야 한다. 화재 cue ID/text/segments 문구/audio GUID는 기준과 동일해야 한다. 원문은 그대로 두고 자막 구간/표시 줄바꿈만 바뀐 경우 구분해 기록한다.

## V2. 콘텐츠 회귀·연기 안내 — SC-003/007

화재: 시작 안내 → 기존 두 선택지 → 오답 피드백/재선택 → 외치기 반응 → 다음 → 상황 복원 → 비상벨 직접 조작 → 완료/복귀를 실행한다. 모든 기존 대사·행동·순서를 유지한다.

자세: 준비 전/관찰 중 숙임은 완료되지 않음 → 준비 완료 → 원리 관찰 → 실제 숙임 연습 → 연속 2초 자동 인정 → 일어서기/한계 안내 → 결과. 새 버튼 요구나 추가 교육 단계가 없어야 한다. 기존 Editor DebugPose/DebugAdvance를 필요시 사용하되 이 결과는 기기 결과가 아니다.

연기 대사는 수정 전후·보존 의미·음성 갱신·segment timing을 대조한다. 문장/의미별 자막, 음성/자막 일치, 주변 공간/편한 범위/중단 가능성, 낮은 자세만으로 안전하지 않음 및 대피 가능 조건을 보존한다. 음성과 불일치하거나 자산이 없으면 해당 검증은 미완료다.

## V3. 소유권·새 누름·전환 — SC-005

메뉴 → 화재 → 메뉴 → 자세 → 메뉴 → 화재를 실행한다. 각 전환과 재시작에서 이전 자막/상태/선택지/콜백 잔류 0건을 확인한다. 버튼을 누른 채 단계/콘텐츠를 바꾸고 이전 pointer click을 전달해도 새 행동은 실행되지 않아야 한다. 모두 뗀 뒤 새 선택 한 번은 한 번만 실행한다.

Editor 도구에서는 새 바인딩 뒤 이전 sink.SetText/Clear와 옛 generation/revision 선택을 호출해 화면·진행이 바뀌지 않음을 검사한다. 두 콘텐츠 외의 새 교육 시나리오는 추가하지 않는다.

## V4. 설정·모달·오류 — SC-004/005

- 음성 중 일시정지/계속하기: 음성·자막·환경·진행 보존, 중복 재생 0건.
- 재시작/이탈 확인 열기/취소/실행: 취소는 기존 진행 유지, 뒤쪽 공유 버튼/비상벨/텔레포트 실행 0건, 실행만 초기화/복귀.
- 자막 끄기: 음성 자막은 숨고 자세 준비/인식/추적 오류 안내는 남음. 비활성 콘텐츠에 설정을 적용해도 현재 자막이 잘못 바뀌지 않음.
- 필수 UI config/음성/행동 연결 누락, 자세 추적 끊김/복구: 기존 오류 정책과 복귀 경로 유지, 완료 0건. 오류 주입은 임시 테스트 인스턴스에서 하고 원본 자산을 저장하지 않음.
- 재진입은 새 체험. 자세 기준 재확인은 기존 명세대로. 기본/150% 설정을 모두 확인.

## V5. Quest 2·제출 경계 — SC-006

기존 Android/OpenXR 설정으로 기기에 실행한다. 레이+트리거로 두 콘텐츠 완료/복귀, 머리 회전·텔레포트 뒤 읽기, 서기/숙이기 중 메뉴 접근, 길게 누름과 모달 입력 차단을 확인한다. Profiler로 변경 전후 불필요한 반복 생성/레이아웃 증가가 없는지 비교한다. 전용 카메라 이동·새 이동 방식은 추가하지 않는다.

기기나 빌드 환경이 없으면 미검증으로 기록한다. PC 시뮬레이션 성공을 기기 성공으로 쓰지 않는다. 단일 공유 체험 UI, XR Origin/AudioListener/EventSystem/XRUIInputModule의 기존 단일 소유를 확인한다. 새 코드/자원/참조가 Assets/_02LWS 밖을 새로 의존하지 않는지 검사한다. unitypackage 실제 내보내기·제출은 이 검증 가이드 실행에 포함하지 않는다.

## 기록

`Assets/_02LWS/Documentation/Validation/SharedExperienceUI.md`에 문서 버전·콘텐츠/단계·기기/입력·글자 설정·기대/실제·증거 경로·수정 사항을 기록한다. 기준 화면/원문 대조/검사 출력도 이 폴더에서 관리한다. V1~V5별 완료/실패/미검증을 분리한다. 단계적 화면 승인 절차는 미확정 제안이므로 자동 완료 조건으로 추가하지 않는다.
