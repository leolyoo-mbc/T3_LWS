# Feature Specification: 바닥에서 올라오는 선택지와 진행 버튼

**Feature Branch**: 기존 `main` 유지. 이번 명세 작성에서 브랜치 생성 없음.

**Feature Directory**: `specs/006-floor-choice-buttons`

**Created**: 2026-11-16

**Status**: Draft

**Input**: 사용자 대화: 기존 화면의 행동 선택지 버튼을 다른 방식으로 대체하고 싶다. 사건을 바라보는 방향의 바닥에서 선택지가 올라오는 그림을 검토한 뒤, “고개 방향 강제까진 필요 없어 지금은. 그냥 저 그림처럼 바닥에서 선택지가 올라오게 하면 될 것 같아”라고 결정했다.

**Scope Update**: 이후 사용자 요청으로 준비 완료, 다음, 다음 연습도 같은 방식으로 이번 명세에 포함한다. 이 명세에서 ‘대상 버튼’은 행동 선택지와 이 세 종류의 진행 버튼을 함께 뜻한다. 기능 식별 경로는 그대로 유지한다.

## Clarifications

### Session 2026-11-16

- Q: 바닥에서 올라오는 선택지를 어느 체험에 적용할까? → A: 화재 사실 알리기와 안전한 대피 경로 판단의 행동 선택지를 모두 변경한다. 처음에는 진행 버튼을 제외했으나, 아래 범위 확장 결정으로 준비 완료/다음/다음 연습도 포함한다.
- Q: 바닥에서 올라온 선택지는 어떻게 누르게 할까? → A: 기존처럼 컨트롤러 레이로 가리키고 트리거로 선택한다. 직접 누르기는 추가하지 않는다.
- Q: 바닥에서 올라오는 선택지의 외형은 무엇으로 할까? → A: C안으로 한다. 기둥, 받침대와 바닥 개폐구 없이 선택지 판만 바닥에서 올라오며 별도 특수 효과는 추가하지 않는다.
- Q: 선택을 마친 뒤 선택지 판은 어떻게 사라지게 할까? → A: 선택 입력을 막고 바닥으로 내려가며 사라진다.
- 범위 확장: 사용자가 준비 완료, 다음, 다음 연습도 같은 방식으로 이번 명세에 포함하도록 요청했다. 세 체험의 해당 진행 버튼을 포함하며, 기존 조작 방식과 단순한 판의 상승/하강 방식을 동일하게 적용한다. 메뉴/설정/확인/결과 화면 버튼은 제외한다.
- 분석 후 확정: 다음 연습은 누르는 즉시 추가 입력을 막고 현재 구역에서 판이 완전히 내려간 뒤 다음 구역으로 이동한다. 준비 완료의 높이 저장과 다른 버튼의 기존 행동은 누르는 순간 실행한다. 배치 검사는 아래 관찰 위치 표와 자세/글자 배율 기준을 따른다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사건과 바닥에서 올라오는 버튼을 함께 보기 (Priority: P1)

체험자는 행동을 판단하거나 준비 완료/다음 진행을 요구하는 단계에서 바닥으로부터 버튼판이 올라오는 것을 보고, 상황과 버튼 내용을 함께 확인한다. 같은 버튼을 기존 화면과 바닥에 중복해서 보지 않는다.

**Why this priority**: 시야를 따라다니는 선택창을 공간 안의 선택 장치로 바꾸는 것이 이번 기능의 핵심이다.

**Independent Test**: 기존 행동 선택 단계 하나를 실행하고, 선택지가 없던 상태에서 바닥으로부터 올라와 표시되는 과정과 사건의 가시성을 확인한다.

**Acceptance Scenarios**:

1. **Given** 행동 선택 단계에 들어가기 전, **When** 해당 단계의 기존 선택 가능 시점이 되면, **Then** 해당 선택지 묶음 하나가 정해진 바닥 위치에서 위로 올라와 나타나고 이전 화면의 행동 선택지는 표시되지 않는다.
2. **Given** 선택지가 올라온 상태, **When** 의도된 체험 위치에서 확인하면, **Then** 사건의 판단 대상과 선택지 전체를 함께 볼 수 있으며 선택지가 판단 대상의 핵심 부분을 가리지 않는다.
3. **Given** 선택 단계에 진입할 때 사용자가 다른 방향을 보고 있는 상태, **When** 선택지가 등장하면, **Then** 고개 방향 때문에 등장이나 체험 진행이 차단되지 않으며 사용자는 자유롭게 돌아볼 수 있다.

---

### User Story 2 - 기존 행동을 공간의 선택지로 고르기 (Priority: P1)

체험자는 공간 안에 올라온 선택지를 컨트롤러 레이로 가리키고 트리거를 눌러 고른다. 표시 방식이 바뀌어도 질문, 선택 문구, 정답 판단, 피드백과 교육 순서는 유지된다.

**Why this priority**: 시각 연출을 바꾸면서 기존 교육 행동과 오답 재시도를 훼손하지 않아야 한다.

**Independent Test**: 같은 단계의 두 선택지를 각각 실행해 기존 결과와 비교하고, 오답 뒤 다시 선택할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 선택지가 완전히 올라와 선택 가능한 상태, **When** 한 항목을 선택하면, **Then** 그 항목에 연결된 기존 행동이 정확히 한 번 실행된다.
2. **Given** 선택지가 올라오는 중이거나 이미 처리 중인 상태, **When** 선택 입력을 유지하거나 반복하면, **Then** 준비되지 않은 선택이나 중복 실행이 발생하지 않는다.
3. **Given** 오답 뒤 같은 판단을 다시 요구하는 단계, **When** 기존 피드백이 끝나 재선택할 수 있게 되면, **Then** 그 단계의 선택지를 다시 사용할 수 있고 이전 입력이 새 선택으로 이어지지 않는다.
4. **Given** 준비 완료, 다음 또는 다음 연습을 요구하는 단계, **When** 해당 버튼을 사용할 수 있는 기존 시점이 되면, **Then** 해당 진행 버튼 하나가 바닥에서 올라오고 기존 화면에는 같은 버튼이 남지 않는다. 레이와 트리거로 실행하면 판이 내려가며 기존 준비/진행 동작이 한 번 실행된다.
5. **Given** 선택 가능한 판이 올라온 상태, **When** 한 항목을 선택하면, **Then** 선택 입력이 즉시 차단되고 판이 바닥으로 내려가며 사라진다. 내려가는 동안 같은 항목이나 다른 항목을 다시 실행하지 않는다.
6. **Given** 다음 연습 버튼이 올라온 상태, **When** 사용자가 누르면, **Then** 추가 입력을 즉시 막고 현재 구역에서 판의 하강을 끝낸 뒤 다음 구역으로 한 번 이동한다. 하강 중 일시정지하면 이동도 기다리며, 재시작/체험 종료 시 대기 중이던 이동은 취소한다.

### User Story 3 - 중단과 체험 전환 뒤 올바른 선택지만 보기 (Priority: P2)

체험자는 선택지를 보는 중에 일시정지하거나 체험을 다시 시작하고 이동하더라도, 현재 체험의 현재 판단에 해당하는 선택지만 사용한다.

**Why this priority**: 공간에 남은 선택지나 이전 선택 입력이 다른 단계의 행동을 실행해서는 안 된다.

**Independent Test**: 선택지 등장 중, 선택 대기 중에 일시정지/재개, 재시작 및 체험 선택 화면 복귀를 실행하고 표시와 입력을 확인한다.

**Acceptance Scenarios**:

1. **Given** 선택지가 등장하거나 선택을 기다리는 중, **When** 일시정지하면, **Then** 등장 동작과 선택 입력이 중단되며 재개 후 현재 단계의 선택 상태로 복구된다.
2. **Given** 특정 체험의 선택지가 표시된 상태, **When** 재시작, 체험 종료 또는 다른 체험으로 전환하면, **Then** 이전 선택지가 남거나 이전 행동이 실행되지 않는다.
3. **Given** 기존에 허용된 이동으로 사용자의 위치가 달라진 상태, **When** 현재 선택지를 확인하면, **Then** 선택지는 공간의 지정 위치에 머물며 사용자의 고개를 따라 움직이지 않는다.

### Edge Cases

- 선택 대상을 바라보지 않은 채 선택 단계에 진입해도 시선 확인이나 특정 방향 유지로 진행을 막지 않는다. 시야 밖 선택지를 찾기 위한 새 안내 체계는 이번 범위에 추가하지 않는다.
- 바닥 높이, 벽, 계단, 문 또는 사건 대상과 선택 장치가 겹치는 배치는 수용하지 않는다. 각 적용 지점의 배치 오류로 확인하고 조정한다.
- 기존에 지원하는 서기/앉기 상태와 글자 크기에서 선택 문구와 선택 영역이 잘리거나 서로 겹치지 않아야 한다.
- 등장 중 누른 입력, 선택 뒤 계속 누른 입력 또는 일시정지 중 입력을 재개 뒤 새 선택으로 처리하지 않는다.
- 선택 장치가 통로나 이동 지점을 가리는 배치는 피한다. 새 물리적 장애물이나 이동 요구를 추가하지 않는다.
- 선택할 항목이 없는 단계에서 빈 선택 장치나 빈 판을 계속 표시하지 않는다.
- 진행 버튼 하나만 필요한 단계에는 그 버튼만 표시하며, 행동 선택지가 아닌 준비 완료/다음/다음 연습을 구분하기 위해 새 선택지를 추가하지 않는다.
- 연기 체험의 준비 완료는 상승 시작이나 상승 완료가 아니라 기존처럼 사용자가 해당 버튼을 실행한 시점에 기준 머리 높이를 저장해야 한다. 준비 안내와 자세 판정 조건을 바꾸지 않는다.
- 다음 연습은 현재 구역에서 하강을 끝낸 뒤 구역을 바꾸고 이전 판/대기 입력을 정리한다. 하강 중 재시작/체험 종료 시 대기 이동도 폐기한다. 새 구역에서 필요한 버튼만 표시한다.

### 배치 검사 기준

| 대상 버튼 | 관찰 위치 | 가리면 안 되는 대상 |
|---|---|---|
| 화재 선택지와 다음 | 기존 화재 체험 시작 위치 | 화재 상황과 비상벨 |
| 연기 준비 완료 | 기존 연기 체험 시작 위치 | 관찰해야 할 연기 |
| 경로 준비 완료 | A 구역 시작 위치 | 주변 대피 경로 |
| 각 계단/엘리베이터 선택지 | 각 대상의 기존 확인 지점, 총 6곳 | 출입구와 판단에 필요한 연기 |
| 다음 연습 | A 구역에서 선택을 마친 각 계단의 확인 지점, 양쪽 완료 경로 검사 | 해당 계단 출입구 |

각 위치에서 기본 글자 100%와 확대 글자 150%를 모두 검사한다. 화재/경로는 기존 지원 범위의 서기/앉기, 연기 준비는 기존 안내대로 서기를 검사한다. 검사 전 실제 관찰 좌표/방향과 자세별 머리 높이를 기록하고 같은 조건으로 반복한다. 기존 설정에서 해당 자세를 지원하지 않으면 근거와 제외 사유를 적고 지원/합격으로 확대하지 않는다. 이 표는 버튼이 표시되는 시점의 배치 검사이며 이후 단계의 이동/비상벨 조작 조건을 바꾸지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ‘화재 사실 알리기’의 행동 선택지와 다음, ‘연기 속 대피’의 준비 완료, ‘안전한 대피 경로 판단’의 경로 선택지/준비 완료/다음 연습을 모두 공간 안의 바닥 상승형 버튼판으로 대체해야 한다. 같은 버튼을 기존 화면과 바닥에 중복 표시하지 않아야 한다.
- **FR-002**: 모든 대상 버튼은 기존 단계가 실행을 허용하는 시점에 바닥에서 위로 올라오는 과정이 보이도록 등장해야 한다. 기둥, 받침대와 바닥 개폐구 없이 버튼판만 표시하며 별도 발광/투명/입자 특수 효과를 추가하지 않는다. 새 시간 제한이나 추가 교육 단계를 넣지 않아야 한다.
- **FR-003**: 대상 버튼은 해당 사건이나 준비/진행 중 관찰할 상황을 보는 방향의 지정된 바닥 위치에 두되, 판단에 필요한 핵심 부분을 가리지 않아야 한다.
- **FR-004**: 대상 버튼의 등장, 사용 가능 여부 또는 체험 진행을 사용자의 고개나 눈의 방향 조건으로 제한하지 않아야 한다. 버튼을 가리켜 고르는 기존 조작은 이 제한과 구분한다.
- **FR-005**: 대상 버튼이 등장한 뒤에는 공간의 지정 위치에 머물러야 하며 사용자 머리나 컨트롤러에 붙어 따라다니지 않아야 한다.
- **FR-006**: 기존 선택 문구, 항목의 의미, 판단 결과, 피드백, 재선택과 이후 교육 흐름을 보존해야 한다. 선택지의 외관으로 정답을 미리 알려주지 않아야 한다.
- **FR-007**: 모든 대상 버튼은 컨트롤러 레이로 가리키고 트리거로 실행해야 한다. 직접 누르기는 추가하지 않는다. 상승이 끝난 후에만 실행할 수 있어야 하며 한 번의 입력으로 기존 행동을 정확히 한 번 실행해야 한다. 등장, 퇴장, 처리 및 중단 상태의 입력은 실행하지 않아야 한다.
- **FR-008**: 대상 버튼을 실행하면 즉시 추가 입력을 막고 해당 버튼 묶음이 바닥으로 내려가며 사라져야 한다. 현재 단계에서 버튼이 더 이상 필요하지 않으면 표시를 정리해야 한다. 오답 재선택에는 기존 피드백 이후 현재 단계에 맞는 선택지가 다시 바닥에서 올라와야 한다. 퇴장 연출로 기존 교육 결과와 피드백의 순서를 바꾸지 않아야 한다.
- **FR-009**: 일시정지 중에는 대상 버튼의 실행과 등장/퇴장 연출을 멈추고, 재개 시 현재 단계의 상태와 기존 안내 재생 지점을 보존해야 한다. 재시작/체험 전환 시 이전 표시와 대기 입력을 정리해야 한다.
- **FR-010**: 기존에 지원하는 글자 크기와 체험 위치에서 대상 버튼의 문구 전체가 읽히고 각 항목을 구별해 실행할 수 있어야 한다. 벽/바닥 관통, 문구 잘림, 항목 간 겹침과 판단 대상 가림을 방지해야 한다.
- **FR-011**: 자막, 상태 안내, 체험 선택 화면, 일시정지/설정/확인/결과 화면은 이번 기능의 교체 대상에서 제외해야 한다. 기존 왼쪽 메뉴 버튼의 일시정지 조작을 유지해야 한다.
- **FR-012**: 제작자는 적용 지점별 대상 버튼의 바닥 위치와 표시 방향을 편집하고 등장 전/후 모습을 확인할 수 있어야 한다. 전체 UI 편집 도구 개편을 요구하지는 않는다.
- **FR-013**: 진행 단계에는 기존 준비 완료/다음/다음 연습 중 필요한 버튼 하나만 제공해야 한다. 준비 완료의 기준 머리 높이 저장과 다른 버튼의 기존 행동은 누르는 순간 실행해야 한다. 다음 연습만 추가 입력을 즉시 막고 현재 구역에서 판이 완전히 내려간 뒤 다음 구역으로 한 번 이동해야 한다. 기존 교육 결과와 전환 조건은 유지하고, 유효한 다음 연습 입력 없이 상승/하강만으로 준비나 진행을 자동 실행하지 않아야 한다.

### Key Entities

- **행동 선택 묶음**: 현재 교육 판단에서 고를 수 있는 항목들과 기존 문구, 행동 및 사용 가능 상태.
- **진행 버튼**: 현재 단계의 준비 완료, 다음 또는 다음 연습 중 하나. 행동 판단의 선택지는 아니며 한 번의 기존 진행 동작을 요청한다.
- **대상 버튼 묶음**: 바닥에서 함께 올라오고 내려가는 현재 단계의 행동 선택 묶음 또는 진행 버튼 하나.
- **선택지 표시 지점**: 사건과 선택지를 함께 관찰할 수 있도록 정한 바닥 위치와 표시 방향.
- **선택지 표시 상태**: 숨김, 등장 중, 선택 대기, 처리 중, 정리 중 및 일시정지 상태. 교육 판단의 결과 자체와 구분한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 세 체험의 모든 적용 대상 단계에서 행동 선택지 또는 준비 완료/다음/다음 연습 버튼이 바닥에서 올라오는 것을 확인할 수 있고, 이전 화면의 같은 버튼이 동시에 표시되는 사례가 0건이다.
- **SC-002**: 배치 검사 기준 표의 모든 위치에서 사건 핵심 대상 가림, 벽/바닥 관통, 선택 문구 잘림 및 항목 간 겹침이 각각 0건이다. 기록한 좌표/방향/머리 높이로 기본 100%/확대 150%와 기존 지원 자세를 반복 확인한다.
- **SC-003**: 기존 선택 결과/오답 재선택/교육 순서의 차이와 중복 실행이 각각 0건이다. 준비 완료의 높이는 클릭 순간 저장하고 다른 버튼의 행동도 기존 실행 시점을 유지한다. 다음 연습은 하강 완료 전 구역 이동 0건, 하강 완료 후 유효한 요청의 이동 정확히 1회다. 유효한 버튼 입력 없이 상승/하강만으로 자동 진행되는 사례는 0건이다.
- **SC-004**: 사건의 반대 방향을 보는 상태에서 단계에 진입해도 고개 방향 때문에 선택지 등장이나 진행이 차단되는 사례가 0건이다.
- **SC-005**: 등장 중/선택 대기 중의 일시정지, 재개, 재시작과 체험 전환 검사에서 이전 선택지 잔류와 입력 오실행이 0건이다.
- **SC-006**: 자막, 상태 안내, 체험 선택 및 일시정지/설정/확인/결과 화면에 이번 상승/하강 연출이 잘못 적용되는 사례가 0건이다.
- **SC-007**: 실제 실행 자료에서 등장 전, 올라오는 과정, 선택 대기, 항목 선택과 바닥으로 내려가 사라지는 과정을 식별할 수 있다. 내려가는 중 추가 행동이 실행되는 사례가 0건이다. 제작자의 배치 검토 결과와 수정 요청을 기록하고, 검토 전 모습을 사용자가 승인한 외관으로 표시하지 않는다.

## Assumptions

### 사용자 확정 사항

- 화면의 행동 선택지를 바닥에서 올라오는 방식으로 바꾼다.
- 사건을 보면서 선택할 수 있는 위치에 배치하되 고개 방향을 강제하지 않는다.
- 선택지뿐 아니라 준비 완료, 다음, 다음 연습도 같은 등장/실행/퇴장 방식으로 변경한다. 자막과 메뉴 화면의 처리 방식 개편은 포함하지 않는다.
- 적용 범위는 ‘화재 사실 알리기’의 행동 선택지와 다음, ‘연기 속 대피’의 준비 완료, ‘안전한 대피 경로 판단’의 경로 선택지와 준비 완료/다음 연습이다.
- 선택 조작은 기존 컨트롤러 레이와 트리거를 유지한다. 버튼에 가까이 가서 직접 누르는 조작은 추가하지 않는다.
- 외형은 C안의 단순한 선택지 판이다. 기둥, 받침대, 바닥 개폐구와 별도 특수 효과 없이 판만 바닥에서 올라온다. C안 선택이 복잡한 홀로그램 재질이나 투명 효과의 요구를 뜻하지 않는다.
- 선택 후에는 추가 입력을 막고 판이 바닥으로 내려가며 사라진다.
- 다음 연습은 판의 하강 완료 후 다음 구역으로 이동한다. 준비 완료와 다른 버튼의 행동은 클릭 순간 실행한다. 배치 검사는 위 위치/자세/글자 배율 기준으로 기록한다.

### 명세 작성 기본값과 검토 중인 아이디어 — 사용자 미확정

- 새 교육 콘텐츠나 새 버튼 문구는 만들지 않고 적용 대상 세 체험의 기존 항목을 사용한다.
- 발로 밟기, 음성 입력과 A/B 직접 배정은 새 요구로 추가하지 않는다.
- 그림의 기계식 받침대, 바닥 개폐구와 청록색 발광은 채택하지 않는다. 기존 선택지의 읽기 쉬운 표현을 단순한 판에 유지하는 것을 기본값으로 둔다.
- 상승 시간, 최종 높이, 사건과의 거리, 판의 기울기와 크기는 배치 검토에서 정할 조정 항목이다. 고정 수치나 특정 바닥 장치 모델을 이번 명세에서 확정하지 않는다.

### 의존성과 검증 한계

- 기존 체험의 선택 가능 시점, 교육 판단, 공용 안내와 입력, 일시정지, 공간 이동 체계에 의존한다. 기존 공용 UI 소유 원칙과 제출 자산 범위를 보존한다.
- 이미지는 검토용 콘셉트이며 현재 구현의 실행 화면이나 외관 승인 증거가 아니다.
- 이번 요청은 명세 작성이다. 실행 코드, 씬, 교육 데이터와 음성을 수정하지 않는다. 계획과 작업 목록 생성 또는 구현 단계로 자동 진행하지 않는다.
- 구현 검증 시 프로젝트 헌법 v1.3.0의 실제 실행 영상, 게임 소리 분리, 재생 확인 및 비추적 자료 보관 규칙을 따른다. 문서만 작성하는 이번 작업에는 새 실행 녹화를 요구하지 않는다.
- 편집기/PC에서의 표시 및 입력 확인과 Quest 실기에서의 가독성, 편안함, 입력 및 성능 확인을 구분한다. 실행하지 않은 환경을 합격으로 처리하지 않는다.
