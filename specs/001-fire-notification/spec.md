## User Scenarios & Testing *(mandatory)*

### User Story 1 - 큰소리로 화재 알리기 (Priority: P1)

학습자는 안내자의 상황 설명과 행동 선택지를 확인하고, ‘큰소리로 알리기’를 선택해 플레이어의 “불이야!” 음성과 주변 사람들이 반응하는 모습을 체험한다. 이를 통해 자신의 행동이 주변 사람들에게 화재 사실을 알리는 과정임을 이해한다.

**Why this priority**: 화재 사실을 알리는 첫 번째 방법이며 콘텐츠의 첫 체험을 구성한다.

**Independent Test**: 콘텐츠 시작부터 해당 행동 선택과 주변 반응까지 체험하여, 비상벨 체험 없이도 큰소리로 알리는 행동과 결과를 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 콘텐츠를 시작한 상태, **When** 첫 안내가 제공되면, **Then** 학습자는 화재 상황 설명과 ‘큰소리로 알리기’를 포함한 행동 선택지를 확인할 수 있다.
2. **Given** 행동 선택을 기다리는 상태, **When** 학습자가 ‘큰소리로 알리기’를 선택하면, **Then** 플레이어의 “불이야!” 음성이 재생된다.
3. **Given** “불이야!” 음성이 재생된 상태, **When** 행동 결과가 제시되면, **Then** 주변 사람들이 반응하며 화재 사실이 전달되는 모습을 확인할 수 있다.
4. **Given** 행동 선택을 기다리는 상태, **When** ‘큰소리로 알리기’ 외의 행동을 선택하면, **Then** 해당 선택이 적절하지 않은 이유를 짧게 설명하고 같은 선택지를 다시 제시한다. ‘큰소리로 알리기’를 선택하기 전에는 다음 체험 단계로 진행하지 않는다.

---

### User Story 2 - 비상벨로 화재 알리기 (Priority: P1)

학습자는 안내자로부터 비상벨의 역할을 듣고 VR 컨트롤러로 비상벨을 직접 눌러, 경보가 주변으로 전파되는 과정을 체험한다.

**Why this priority**: 큰소리로 알리기와 함께 확정된 두 번째 핵심 교육 행동이다.

**Independent Test**: 비상벨 체험 시작 상태에서 역할 설명, 직접 누르기, 경보 전파까지 확인하여 해당 교육 목표를 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 비상벨 체험 시작 상태, **When** 안내자가 설명하면, **Then** 학습자는 비상벨이 화재 사실을 알리는 역할을 한다는 설명을 받는다.
2. **Given** 역할 설명이 끝나고 비상벨 조작을 기다리는 상태, **When** 학습자가 VR 컨트롤러로 움직이는 가상 손을 비상벨에 가져가 버튼을 밀어 누르면, **Then** 복도에 경보음이 울리고 주변 사람들이 하던 행동을 멈춰 반응하는 모습을 확인할 수 있다.
3. **Given** 비상벨 조작을 기다리는 상태, **When** 학습자가 아직 누르지 않으면, **Then** 비상벨을 누르는 실습이 완료된 것으로 처리되지 않는다.

### User Story 3 - 같은 상황에서 두 방법을 순서대로 체험하기 (Priority: P2)

학습자는 큰소리로 알리기의 결과를 확인한 뒤 같은 화재 상황으로 돌아가 비상벨 체험을 진행한다. 두 장면을 연속된 실제 화재 사건으로 혼동하지 않고, 같은 상황에서 두 방법의 결과를 확인한다.

**Why this priority**: 두 핵심 체험을 사용자가 정한 하나의 교육 흐름으로 연결한다.

**Independent Test**: 큰소리로 알리기의 결과 직후부터 상황 복귀와 비상벨 안내 시작까지 검증한다.

**Acceptance Scenarios**:

1. **Given** 큰소리로 알리기의 결과 연출이 끝나 ‘다음’ 버튼이 표시된 상태, **When** 학습자가 ‘다음’을 선택하면, **Then** 최초와 같은 화재 상황으로 돌아가고 비상벨 역할 설명이 시작된다.
2. **Given** 같은 상황으로 돌아온 상태, **When** 비상벨 설명과 실습이 진행되면, **Then** 이전 체험의 음성이나 주변 반응이 겹쳐 두 방법의 결과를 혼동시키지 않는다.
3. **Given** 큰소리로 알리기의 결과 연출이 끝난 상태, **When** 학습자가 ‘다음’을 선택하지 않으면, **Then** 상황 복귀나 비상벨 역할 설명이 자동으로 시작되지 않는다.

### User Story 4 - 체험을 마치고 콘텐츠 선택 메뉴로 돌아가기 (Priority: P2)

학습자는 콘텐츠 선택 메뉴에서 콘텐츠 1을 시작하고, 두 방법의 체험을 마치면 완료 안내를 확인한 뒤 메뉴로 돌아갈 수 있다.

**Why this priority**: 체험 진입과 종료 경로를 제공하여 콘텐츠 1을 하나의 독립 콘텐츠로 이용할 수 있게 한다.

**Independent Test**: 콘텐츠 선택 메뉴에서 콘텐츠 1에 진입하고, 체험 완료 상태에서 메뉴 복귀 버튼을 선택하여 메뉴로 돌아오는 것을 검증한다.

**Acceptance Scenarios**:

1. **Given** 콘텐츠 선택 메뉴가 표시된 상태, **When** 학습자가 콘텐츠 1을 선택하면, **Then** 콘텐츠 1의 첫 안내가 시작된다.
2. **Given** 비상벨 경보 전파 연출이 끝난 상태, **When** 완료 안내가 표시되면, **Then** 콘텐츠 선택 메뉴로 돌아가는 버튼을 사용할 수 있다.
3. **Given** 완료 안내가 표시된 상태, **When** 학습자가 메뉴 복귀 버튼을 선택하면, **Then** 콘텐츠 선택 메뉴가 표시된다.
4. **Given** 콘텐츠 선택 메뉴가 표시된 상태, **When** 학습자가 콘텐츠 항목을 확인하면, **Then** 콘텐츠 1만 표시되며 다른 콘텐츠 후보나 ‘준비 중’ 항목은 표시되지 않는다.
5. **Given** 체험을 완료하고 메뉴로 돌아온 상태, **When** 콘텐츠 1을 다시 선택하면, **Then** 이전 경보와 주변 반응이 남지 않은 초기 상태에서 첫 안내가 시작된다.
6. **Given** 체험의 설명·입력 대기·결과 연출 중 어느 단계에 있는 상태, **When** 학습자가 메뉴 복귀 기능을 사용하면, **Then** 현재 체험을 종료하고 콘텐츠 선택 메뉴로 돌아간다. 콘텐츠 1을 다시 선택하면 초기 상태에서 첫 안내부터 시작한다.

7. **Given** 콘텐츠 선택 메뉴에서 시작한 상태, **When** 콘텐츠 1 진입과 메뉴 복귀를 반복하면, **Then** 같은 Unity 씬 안에서 해당 별도 공간으로 이동하며, 선택하지 않은 공간의 소리·연출·입력이 체험에 간섭하지 않는다.

8. **Given** 메뉴 또는 콘텐츠 1을 사용하는 상태, **When** 공간을 전환하면, **Then** 동일한 공용 기본 조명과 XR·입력·중단 감지 객체가 계속 활성 상태로 유지되며, 체험 전용 화재 조명과 연출은 해당 공간에서만 작동한다.

### Edge Cases

- 행동 선택 또는 비상벨 입력을 연속으로 반복해도 같은 음성·경보·단계 전환이 중복 실행되어 흐름을 건너뛰지 않아야 한다.
- 행동을 기다리는 동안 입력이 없어도 해당 행동을 수행한 것으로 처리하지 않아야 한다.
- 현재 단계와 관계없는 입력으로 다음 단계가 시작되지 않아야 한다.
- 설명이나 결과 연출 중 메뉴로 돌아가도 체험의 음성·경보·주변 반응이 메뉴에서 계속 재생되지 않아야 하며, 재진입 시 중단한 단계가 재개되지 않아야 한다.
- 상황 복귀 후에도 이전 단계의 반응이 남아 비상벨을 누르기 전에 경보가 이미 전파된 것처럼 보이지 않아야 한다.
- 헤드셋을 벗거나 시스템 메뉴를 열어 앱이 중단되면 체험 진행과 음성·연출을 멈춰야 한다. 같은 실행 중인 앱으로 복귀하면 중단된 단계의 처음부터 재진행하되, 완료한 이전 단계 전체를 다시 시작하거나 다음 단계로 건너뛰지 않아야 한다. 재진행 시 이전 음성·연출과 겹치지 않아야 한다. 앱 종료 후 재실행은 이 복귀 규칙의 대상이 아니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 콘텐츠는 안내자의 화재 상황 설명과 행동 선택지 제시로 시작해야 한다. (Story 1-1)
- **FR-002**: 학습자가 ‘큰소리로 알리기’를 선택하면 플레이어의 “불이야!” 음성을 재생해야 한다. 실제 발성을 완료 조건으로 요구하지 않는다. (Story 1-2)
- **FR-003**: 큰소리로 알린 결과로 주변 사람들이 반응하고 화재 사실이 전달되는 모습을 보여줘야 한다. (Story 1-3)
- **FR-004**: 큰소리로 알리기의 결과 연출이 끝나면 ‘다음’ 버튼을 표시해야 한다. 학습자가 이를 선택하면 최초와 같은 화재 상황으로 돌아가야 하며, 선택 전에는 자동 전환하지 않아야 한다. (Story 3-1, 3-3)

- **FR-014**: 비상벨 경보 전파 연출이 끝나면 완료 안내와 콘텐츠 선택 메뉴로 돌아가는 버튼을 표시해야 하며, 버튼 선택 시 해당 메뉴로 돌아가야 한다. (Story 4-2, 4-3)
- **FR-015**: 안내자의 상황 설명, 비상벨 역할 설명 및 오답 피드백은 음성과 같은 내용을 전달하는 자막으로 제공해야 한다. 화면이나 공간에 등장하는 안내 캐릭터는 포함하지 않는다. 각 안내를 확인할 때 음성과 대응 자막을 함께 확인할 수 있어야 한다. 이 명세에서 ‘안내자’는 이 음성 안내를 뜻한다. (Story 1-1, 1-4, 2-1)

- **FR-017**: 체험 중 모든 단계에서 콘텐츠 선택 메뉴로 돌아가는 기능을 제공해야 한다. 메뉴 복귀 시 체험의 음성·경보·주변 반응과 진행을 종료하고, 콘텐츠 1 재진입 시 처음부터 시작해야 한다. 중단한 단계 이어하기는 제공하지 않는다. (Story 4-6, Edge Cases)

- **FR-019**: 헤드셋을 벗거나 시스템 메뉴를 열어 앱이 중단되면 현재 체험의 진행·음성·연출을 멈춰야 한다. 같은 실행 중인 앱으로 복귀하면 중단된 체험 단계의 처음부터 다시 진행해야 한다. 단계는 상황 설명, 행동 선택 대기, 큰소리로 알리기 결과, ‘다음’ 선택 대기, 상황 복귀, 비상벨 역할 설명, 비상벨 누르기 대기, 경보 전파 결과, 완료 안내로 구분한다. 입력 대기 단계로 복귀하면 해당 입력을 다시 기다리며, 결과 단계로 복귀하면 해당 결과 연출을 처음부터 재생한다. 앱 중단 복귀는 메뉴 복귀 후 재진입 시 전체 체험을 초기화하는 FR-017과 구분한다. (Edge Cases)
- **FR-020**: 앱 설치 후 최초 실행을 포함하여 인터넷 연결 없이 콘텐츠 선택 메뉴, 모든 음성·자막·연출·상호작용, 완료 안내 및 메뉴 복귀를 이용할 수 있어야 한다. 체험에 필요한 자료를 실행 시 내려받도록 요구해서는 안 된다.

- **FR-023**: 공용 기본 조명·XR 플레이어·입력 처리·공간 전환·앱 중단 감지는 메뉴와 체험에서 같은 객체를 사용해야 한다. 공간 전환으로 공용 객체가 꺼지거나 중복 생성되지 않아야 하며, 체험 전용 연출·소리·입력의 정리와 독립성은 유지해야 한다. (Story 4-8)

### Key Entities

- **체험 단계**: 현재 설명, 입력 대기, 행동 결과, 상황 복귀 중 어느 과정에 있는지를 나타낸다.
- **학습자 행동**: ‘큰소리로 알리기’ 선택 또는 비상벨 직접 누르기. 각 행동은 해당 단계의 결과와 연결된다.
- **화재 상황과 주변 사람들**: 두 방법의 체험 배경이며, 행동 전후의 반응으로 화재 사실이 전달되는 결과를 나타낸다.
- **비상벨**: 역할 설명과 직접 조작의 대상이며, 누르면 경보 전파 결과를 제공한다.

사용자 확정: 편집 모드에서는 모든 스페이스를 활성화해 배치를 확인한다. 구현은 MenuSpace·FireNotificationSpace를 활성화한 씬을 저장하는 방식이다. Play 시작 시 기존 ContentSceneNavigator.Start가 메뉴만 활성화하고 체험 공간을 끈다. startOnSceneEntry=false를 유지해 교육은 선택 후 시작한다. Play 종료 시 편집 상태의 두 공간 활성화로 복원되는지 확인한다. Play 중 전체 표시 기능은 추가하지 않는다.
