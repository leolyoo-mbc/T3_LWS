# Quickstart Validation: 안전한 대피 경로 판단

구현 후 재실행할 절차와 2026-11-13 검증 상태다. 실제 결과는 [RouteAcceptance](../../Assets/_02LWS/Documentation/Validation/RouteAcceptance.md)에 집계했다. [상태 모델](data-model.md)과 [UI/통합 계약](contracts/route-experience.md)을 기준으로 확인한다.

## 1. 준비

Unity 6000.3.26f1로 기존 FireNotification.unity를 열고 사용자 변경, 씬 dirty 상태를 확인한다. 열린 프로젝트를 별도 batch Editor로 동시에 실행하지 않는다. 기존 XR Simulator를 사용하고 새 패키지를 설치하지 않는다.

```powershell
git -C 'E:/projects/T3_LWS' status --short
unity --help
unity status --project-path 'E:/projects/T3_LWS' --format json
```

CLI는 실행 시 unity-cli 스킬과 현재 help로 옵션을 확인한다. discovery가 다르면 실제 명령을 사용하고 연결 오류를 숨기지 않는다.

## 2. 구성, 도메인 검사

| Editor 메뉴 | 진입점 / 기대 결과 |
|---|---|
| Tools > LWS > Validate Shared UI | 기존 SharedUIContractAudit.CheckScene(): 공용 구성 위반 0개 |
| Tools > LWS > Validate Route Configuration | 신규 RouteIntegrationChecks.ValidateConfiguration(): ID, 배치, 도착 영역, 이동 연결, 필수 cue 누락 0개 |
| Tools > LWS > Validate Route Domain | 신규 RouteDomainChecks.Run(): 직접/우회/오답 후 완료, 미방문, 재방문, 중복/낡은 입력, 중단 assertion 전부 통과 |

두 메뉴/진입점은 구현됐다. 도메인 69개, 원본 경로 통합 164개와 별도 결과 추적 복구 검사, 최종 수신 경로 통합 166개, 기존 두 콘텐츠 회귀 49개가 통과했다. 새 테스트 패키지 없이 Editor-only assertion runner로 실행하고 실패 시 사례명과 예외를 남긴다. 검증 수와 통과 수는 실제 출력으로 보고한다.

## 3. 실제 판단, 이동

메뉴 → 세 번째 콘텐츠 → 준비 → A 안내/판단 → A 완료 안내 → 다음 연습 → B 도입/판단 → B 완료 안내 → 공용 결과 순서로 실행한다.

| 사례 | 조작 | 기대 결과 |
|---|---|---|
| A 기본 | 계단 앞 이동, 대피 선택 | 방향/정답 사전 지시 없이 완료 |
| 엘리베이터 | 확인 지점에서 이용 선택 | 탑승 없음, 이유 음성/자막 후 재선택 |
| B 직접 | 막힌 계단 미방문, 이용 가능한 계단 선택 | 완료, 우회 허위 표시, 미방문 감점 없음 |
| B 우회 | 막힌 계단에서 다른 경로, 직접 다른 계단으로 이동/선택 | 완료 + 우회 수행 |
| B 오답 후 완료 | 막힌 계단 진입 선택 후 피드백, 재판단/우회 | 위험 공간 이동 0건, 최초 오답 보존, 피드백 후 완료 |
| 재방문 | 이용 가능한 계단에서 다른 경로 선택 후 떠났다가 복귀 | 같은 계단 재선택 가능 |
| 대상 변경 | 한 대상 UI에서 다른 지점으로 이동 | 이전/원격 대상 선택 실행 0건 |
| A→B 전환 성공 | B 공간 활성화/시작 위치 이동/UI Recenter 후 TransitionDone 전달 | 현재 실행의 Transition에서만 수락, B 안내 1회 시작 |
| 중복/낡은 전환 완료 | 완료를 반복 전달하거나 재시작 이전 실행 번호로 전달 | false로 거부, B 안내 재시작이나 추가 진행 없음 |
| 전환 실패 | B 공간/시작 위치 전환 실패 조건으로 실행 | B 안내 시작 없음, 오류 안내와 메뉴 복귀 가능 |
| 전환 중 중단 | 중단 중 완료 전달 후 복구 | 중단 중 거부, 복구 후 실제 전환 상태 재확인과 유효한 재전달로만 진행 |

A/B의 출발, 계단 방향, 엘리베이터 위치 모두 다른지 실제 화면으로 확인한다. 앵커는 인접 지점만, 양쪽 모두 중립 표시여야 한다. 연기 속, 벽 너머 이동 0건, 연기를 통과해야 하는 우회 구간 0곳이어야 한다. 확인 지점에서 계단/연기를 UI가 가리지 않아야 한다.

## 4. 중단, 설정, 기존 콘텐츠 회귀

Play에서 신규 `Tools > LWS > Validate Route Integration` / `RouteIntegrationChecks.RunPlayMode()`를 실행하도록 구현한다. 합성 입력과 실제 컨트롤러 결과를 구분한다.

- Explore/Decision/Feedback/Transition의 pause, 시스템 중단, 추적 상실을 각각 복구한다. 예약 직후 차단한 이동이 복구 후 실행되지 않아야 한다.
- 누른 채 화면 전환, 빠른 중복 선택, 이전 실행 음성 완료에서 자동/중복 진행 0건. 복구 후 새 입력이 필요하다.
- 기본/150%, 자막 끄기, 음량 0으로 안내, 피드백, 결과를 확인한다. 필수 문구 잘림/겹침 0건. 자막을 꺼도 대상, 조작, 버튼은 남는다.
- 메뉴→화재 전체→메뉴→자세 전체→메뉴→경로 전체→메뉴→화재로 왕복한다. 비상벨 이동/조작, 자세 2초 인식/이동 금지, 경로 이동 정책이 유지되어야 한다.
- A/B 재시작, 메뉴 복귀에서 이전 연기, 예약, 선택, 기록 잔류 0건. 신규 음원 전체의 발음, 억양, 대본/자막 일치와 청취 승인 여부는 별도 기록한다.

## 5. 공간 구성과 사용자 외관 확인

A/B 각각 시작점, 복도 중간, 계단 앞, 엘리베이터 앞에서 실제 실행 화면을 확인한다. 복도 전체, 문과 창문의 반복과 비례, 벽과 문틀의 깊이, 천장과 조명, 계단참과 난간 연결, 엘리베이터 문과 테두리를 확인할 수 있는 영상과 주요 위치 화면을 제공한다(FR-017/SC-008).

구조물의 끊김과 틈, 어색한 비례, 재질 크기의 불일치, 조명 누락, 판단 대상 가림을 점검한다. A/B의 마감과 구조가 같은 학교로 읽히는지 확인하고 장식물 수나 텍스처 해상도만으로 공간 구성 요구를 통과시키지 않는다.

T036의 공통 증거 경로에 원본을 보관하고 `Assets/_02LWS/Documentation/Validation/RouteVisualReview.md`에 확인 위치, 대표 자료 직접 링크, 사용자 검토 결과, 수정 요청과 재검토 결과를 기록한다. 사용자에게 재생 가능한 실제 실행 자료를 제공하고 기능 검증 결과와 외관 승인 결과를 구분한다. 승인 대기/수정 요청 상태를 승인으로 표시하거나 T036을 완료 체크하지 않는다.

세 번째 콘텐츠의 결과를 사용자가 수용한 뒤 기존 두 콘텐츠에 적용할 범위를 별도로 결정한다. 기존 두 콘텐츠의 외관 수정은 이번 구현에 포함하지 않는다. 특정 학교 재현이나 Blender 사용은 필수가 아니며 사진을 참고하거나 도구를 사용한 사실 자체는 품질 검증을 대신하지 않는다.

## 6. 성능, 빌드, import

동일 머신/품질에서 메뉴, 기존 두 콘텐츠, A/B를 워밍업 10초 후 30초씩 3회 측정한다. CPU/GPU median/p95, 입자/batch, 녹화 여부, refresh rate를 남기고 미지원 값은 미측정으로 쓴다. 시각 선택 피드백 1초는 계획 목표이며 실제 안전 시간 기준이 아니다.

기존 Android 설정으로 개발 빌드를 만들어 APK/로그를 Artifacts에 보관한다. Quest 2에서 이동, 돌아서기, 연기 관찰, 150% 읽기, 중단 복구, 성능을 확인한다. 72 Hz/13.9 ms 참고값을 사용자 확정 기준으로 사용하지 않는다. Editor만 실행했다면 Quest 미검증이다.

비-UPM 필수 자산이 _02LWS 안인지 검사하고 기존 ExportImport 지침에 따라 별도 프로젝트 가져오기를 확인한다. 참조/컴파일과 실제 Play/기기 실행 결과는 분리하며 미실시를 통과로 표시하지 않는다.

## 7. 화면, 소리 증거와 완료 보고

`Artifacts/Validation/VisualEvidence/YYYYMMDD-HHmmss-safe-evacuation-route/`에 실제 실행 MP4와 verification.md를 보관한다. 1920×1080 이상, 30fps 이상이며 프레임 복제/단순 확대 없이 실제 화면을 캡처한다. 정상, 오답, 우회, 직접 완료, 결과, 공용 회귀 구간을 포함한다.

게임 소리만 녹음하고 다른 앱, 마이크는 제외한다. 새 방식/입력 설정은 다른 앱 유음 + Unity 무음/유음 구간으로 분리를 검증한다. 다른 앱을 끄거나 음소거한 것으로 대신하지 않는다. 저장한 MP4를 실제 재생해 글자, 움직임, 게임 소리, 동기화를 확인하며 오디오 트랙 존재만으로 통과하지 않는다.

녹화, 소리, 화질 기준 불가 시 최선의 영상/원본 스크린샷/분리 게임 소리 등 대체 자료와 사유, 실제 조건, 미검증을 남긴다. 전체 PC 소리 녹음으로 우회하지 않는다. 실행 자체가 불가능하면 실제 Editor 화면과 실행 미검증을 기록한다.

```powershell
git -C 'E:/projects/T3_LWS' check-ignore 'Artifacts/Validation/VisualEvidence/example/verification.md'
git -C 'E:/projects/T3_LWS' ls-files -- 'Artifacts/Validation/VisualEvidence/'
git -C 'E:/projects/T3_LWS' diff --check
```

example은 실제 폴더로 바꾼다. ignore 적용, 검증 원본 추적 0건을 확인한다. 완료 보고에는 대표 MP4/대체 파일을 직접 링크하고 Editor/Quest/import/청취 결과와 한계를 각각 쓴다.

## 8. 현재 승인/실행 상태

Android 개발 APK와 별도 신규 프로젝트 Import/컴파일/세 콘텐츠 Play 확인을 마쳤다. 자세한 수신 범위와 실제 원본 링크는 RouteAcceptance.md, RouteExportImport.md를 따른다. 신규 음원 7개/외관의 사용자 승인, 최종 영상의 세밀한 소리 동기화 청취와 실제 Quest 2는 미완료다. T028/T032/T034/T036을 체크하지 않는다. 계단 확인 지점은 UI 앞 표지 겹침을 막기 위해 실제 제작에서 입구 쪽 3m로 조정했으며 안전 거리 기준이 아니다.
