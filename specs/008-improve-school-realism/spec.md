# Feature Specification: 학교 건축 외형과 공간 구조의 사실감 개선

**Feature Branch**: 기존 `main` 유지. 명세 작성에서 브랜치 생성 없음.

**Feature Directory**: `specs/008-improve-school-realism`

**Created**: 2026-11-17

**Status**: Draft, 대화에서 확정한 요구를 정리한 명세. 구현과 결과 외관 승인은 미완료.

**Input**: 전체 콘텐츠의 문과 창문을 실제 학교에 맞게 개선한다. 콘텐츠 3의 엘리베이터와 교실 문 중복 배치, 위가 막힌 계단 구조를 수정한다. 실제 화면을 하나씩 검토한 후 조명 개선과 전체 콘텐츠의 걸레받이 제거를 확정했다. 인물, 바닥 재질, 콘텐츠 2의 빈방 구성은 유지한다.

## Clarifications

### Session 2026-11-17

**→ Q:** 창문 너머의 바깥 풍경도 이번 개선에 포함할까? → **A:** 창문 자체만 개선한다. 창틀, 창짝, 레일, 유리 표현을 다듬고 외부 풍경은 추가하지 않는다.

**→ 후속 확정.** 엘리베이터 출입구 2곳의 문짝 4개와 프레임도 외형 개선에 포함한다. A는 확인된 겹침을 수정하고 B는 실제 겹침이 확인된 출입구만 이동한다. 변경 대상과 근거를 기록하고 겹침이 없으면 위치를 유지한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 실제 학교 같은 문과 창문 관찰 (Priority: P1)

체험자는 세 콘텐츠를 둘러보며 실제 학교에서 볼 법한 비례와 세부 형태를 가진 문과 창문을 본다. 문과 창문은 주변 벽에 자연스럽게 연결되어 건물의 일부로 읽힌다.

**Why this priority**: 사용자는 전체 콘텐츠의 문과 창문 모델이 사실적이지 않다고 지적했고, 실제 학교를 기준으로 개선하는 방향을 선택했다.

**Independent Test**: 세 콘텐츠에 존재하는 모든 문과 창문을 목록화하고 각 유형을 정면과 사선에서 확인한다. 반복 배치된 모델도 벽과의 접합 상태를 각각 확인한다.

**Acceptance Scenarios**:

1. **Given** 기존 문과 창문, **When** 변경 후 정면과 사선에서 보면, **Then** 문짝과 문틀, 창짝과 창틀의 구분 및 깊이가 보이고 실제 학교에 맞는 비례로 읽힌다.
2. **Given** 손잡이와 유리를 가진 문, **When** 가까이서 보면, **Then** 손잡이의 부착부와 형태, 유리와 이를 고정하는 틀이 구분되며 단순한 막대와 색칠한 판처럼 보이는 인상이 줄어든다.
3. **Given** 서로 용도가 다른 문, **When** 교실 문과 계단실 문을 비교하면, **Then** 용도에 맞는 외형을 갖추며 모든 출입구를 같은 형태로 획일화하지 않는다.
4. **Given** 기존의 닫힌 문과 열린 문, **When** 교체 후 관찰하면, **Then** 교육 상황에 필요한 개폐 상태가 유지되고 창틀과 문틀 주변에 의도하지 않은 배경 틈이나 벽 관통이 없다.
5. **Given** A/B의 엘리베이터 출입구 2곳, **When** 정면과 사선에서 보면, **Then** 문짝 4개의 두께와 가운데 맞물림, 프레임 깊이 및 금속 표면이 구분되며 기존 판단 위치와 선택 동작은 유지된다.

### User Story 2 - 모순 없는 대피 경로 공간 관찰 (Priority: P1)

체험자는 콘텐츠 3에서 교실 문과 분리된 엘리베이터 출입구, 다음 층으로 이어지는 구조가 보이는 계단실을 보고 대피 경로를 판단한다.

**Why this priority**: 엘리베이터 뒤로 교실 문이 드러나고 계단 끝이 벽으로 막힌 모습은 대피 통로라는 공간의 의미를 훼손한다.

**Independent Test**: 콘텐츠 3의 A/B 상황에서 엘리베이터를 정면과 양쪽 사선으로 확인하고, 네 계단실의 입구와 확인 지점에서 상부 구조를 살핀다.

**Acceptance Scenarios**:

1. **Given** A/B 상황의 엘리베이터, **When** 정면과 양쪽 사선에서 보면, **Then** 교실 문짝이나 유리, 문틀이 엘리베이터 뒤나 옆 틈에서 중복 출입구처럼 드러나지 않는다.
2. **Given** 각 계단실, **When** 입구와 확인 지점에서 위를 보면, **Then** 계단 끝에 계단참과 다음 층으로 이어지는 공간이 보이며 벽과 평평한 천장이 진행 방향을 막지 않는다.
3. **Given** 구조가 수정된 A/B 상황, **When** 엘리베이터와 계단을 판단하면, **Then** 기존 이용 가능/불가 구분과 연기로 막힌 경로의 의미가 유지된다.
4. **Given** 이용 가능한 계단에 도착한 사용자, **When** 대피를 선택하면, **Then** 기존 경로 선택 체험이 완료되며 계단을 실제로 오르는 새 조작은 요구하지 않는다.

### User Story 3 - 얼룩진 조명과 걸레받이 없는 실내 (Priority: P1)

체험자는 천장등 주위의 과한 흰 번짐과 검은 얼룩이 정리된 실내를 본다. 벽 아래 걸레받이는 전체 콘텐츠에서 제거된다.

**Why this priority**: 사용자는 천장등 주변 빛이 어색하다고 확인했고, 걸레받이는 보완 대신 전부 없애는 방향을 선택했다.

**Independent Test**: 세 콘텐츠의 실내와 콘텐츠 3의 A/B 상황을 둘러보며 각 조명 유형과 벽 하부를 확인한다.

**Acceptance Scenarios**:

1. **Given** 콘텐츠 1과 2의 천장등 주변, **When** 변경 전과 같은 시점에서 비교하면, **Then** 지적된 좌우의 흰 빛 덩어리와 바로 위 검은 얼룩이 눈에 띄는 문제가 해소되고 사용자가 개선을 승인한다.
2. **Given** 전체 콘텐츠의 조명, **When** 문과 계단, 비상벨 및 안내를 관찰하면, **Then** 조명 조정 후에도 대상을 식별할 수 있고 다른 공간에 새로운 빛 얼룩이 생기지 않는다.
3. **Given** 세 콘텐츠와 A/B 상황의 벽 하부, **When** 둘러보면, **Then** 걸레받이가 남아 있지 않고 제거 자리에 빈 배경, 벽 아래 틈 또는 떠 있는 잔여 부품이 드러나지 않는다.
4. **Given** 걸레받이가 제거된 공간, **When** 변경 전후를 비교하면, **Then** 바닥 재질은 유지되며 걸레받이 제거를 이유로 다른 띠 장식이나 수납장을 추가하지 않는다.

---

### User Story 4 - 실제 화면으로 한 항목씩 결과 검토 (Priority: P2)

사용자는 변경 내용을 한꺼번에 설명받는 대신 실제 프로젝트 화면에서 항목별로 확인한다. 제작자는 외관 승인과 기존 체험의 정상 진행을 구분해 기록한다.

**Why this priority**: 사용자는 설명만으로 이해하기 어렵다고 했으며 실제 화면을 하나씩 보는 방식을 요청했다.

**Independent Test**: 변경 항목별 실제 실행 화면과 전후 자료를 제시하고 승인 결과를 기록한 뒤, 세 체험의 기존 진행을 확인한다.

**Acceptance Scenarios**:

1. **Given** 변경한 외관 항목, **When** 사용자에게 제시하면, **Then** 항목 하나당 무엇을 봐야 하는지 짧게 설명한 실제 화면이 제공되고 승인 또는 수정 요청이 개별 기록된다.
2. **Given** 변경된 세 콘텐츠, **When** 진입, 핵심 행동, 결과, 메뉴 복귀를 수행하면, **Then** 기존 진행과 이동이 유지된다. 콘텐츠 3은 직접 안전한 계단 선택과 막힌 계단에서 우회를 모두 확인한다.
3. **Given** 자동 검사와 사용자 검토 결과, **When** 완료 여부를 기록하면, **Then** 검사 통과를 외관 승인으로 대신하지 않고 미승인 항목과 기기 미검증 항목을 구분한다.

### Edge Cases

**→ 개구부 크기 차이.** 같은 유형의 문과 창문을 크기가 다른 위치에 적용해도 프레임과 손잡이 비례가 찌그러지거나 벽을 관통해서는 안 된다.

**→ 사선과 낮은 시점.** 문 옆으로 몸을 기울이거나 콘텐츠 2에서 자세를 낮출 때 벽 뒤의 빈 배경이나 미완성 뒷면이 드러나지 않아야 한다.

**→ 연기로 가려진 계단.** 콘텐츠 3의 연기 있는 계단도 구조 수정 대상이다. 상태를 읽을 수 있는 범위에서 형상을 확인하되 연기를 제거하거나 안전한 경로로 바꾸어 검증을 통과시키지 않는다.

**→ 걸레받이에 가려진 틈.** 제거로 접합부 문제가 드러나면 벽과 바닥 연결을 보완한다. 바닥 재질 변경이나 새 하부 띠 추가로 대체하지 않는다.

**→ 기능이 연결된 문.** 외형 교체 때문에 기존 진행, 가림, 충돌, 효과 발생 위치가 달라지지 않아야 한다. 기존에 없던 문 열기 기능을 추가하지 않는다.

**→ 검증 환경 제약.** 실행 영상이나 소리 기준을 충족하지 못하면 확보한 실제 자료와 원인, 확인하지 못한 항목을 남긴다. 편집 화면을 실제 실행 결과로 표시하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**→ FR-001.** 전체 세 콘텐츠에 존재하는 문과 창문을 실제 학교 외형을 기준으로 개선해야 한다. 현재 대상은 실내 문 17개, 큰 창문 10개와 엘리베이터 출입구 2곳의 문짝 4개 및 프레임이며, 구현 직전 현재 씬과 대조해 유형과 배치 목록을 고정하고 누락 없이 적용 여부를 확인해야 한다. 창문은 창틀, 창짝, 레일과 유리 표현 자체를 대상으로 하며 창문 너머의 외부 풍경 제작은 포함하지 않는다.

**→ FR-002.** 문짝 두께, 문틀 깊이, 손잡이, 창짝과 창틀, 유리 고정부 등 보이는 구성 요소를 용도에 맞게 구분해야 한다. 특정 학교나 제조사 제품의 정확한 복제 또는 시설 인증을 요구하지 않는다.

**→ FR-003.** 문과 창문은 벽의 개구부와 맞물려야 하며 사용자가 보는 정면, 사선, 낮은 시점에서 의도하지 않은 틈, 관통, 미완성 뒷면이 드러나지 않아야 한다.

**→ FR-004.** 콘텐츠 3의 A/B 상황 모두에서 엘리베이터와 교실 출입구의 중복 배치를 해소해야 한다. A Classroom04의 확인된 겹침을 수정하고, B는 실제 겹침이 확인된 출입구만 이동하며 겹침이 없으면 위치를 유지해야 한다. 변경 대상, 근거 화면과 변경 전후 위치를 기록해야 한다. 필요한 인접 벽과 개구부는 조정할 수 있으나 엘리베이터 위치, 기존 판단 앵커와 선택 동작 및 이동 지점에서의 접근성을 유지해야 한다.

**→ FR-005.** 콘텐츠 3의 네 계단실은 계단참과 다음 층으로 이어지는 공간을 보여야 한다. 계단 끝을 벽이나 천장이 막는 구조를 제거해야 하며 실제 층간 이동을 새 기능으로 추가하지 않는다.

**→ FR-006.** 천장등 주변의 과한 흰 번짐과 검은 얼룩을 개선하고 전체 대상 공간에서 주변 밝기와 음영이 자연스럽게 이어지도록 해야 한다. 조명 변경 때문에 비상벨, 문, 계단, 안내의 식별이 어려워져서는 안 된다.

**→ FR-007.** 전체 세 콘텐츠 및 A/B 상황의 걸레받이를 제거해야 한다. 남은 조각이나 제거로 생긴 벽과 바닥의 틈이 없어야 한다. 문틀, 창틀, 계단 난간, 천장 마감은 걸레받이로 간주해 일괄 제거하지 않는다.

**→ FR-008.** 현재 인물 모델, 바닥 재질과 무늬 비율, 콘텐츠 2의 빈방 구성을 유지해야 한다. 게시판, 가구, 수납장 추가, 인물 교체 및 벽과 바닥 재질의 전면 변경은 이번 범위에서 제외한다. 조명 변화로 같은 재질의 보이는 밝기가 달라지는 것은 허용한다.

**→ FR-009.** 기존 세 콘텐츠의 교육 문구, 행동 선택, 판정 기준, 비상벨 조작, 자세 인식, 경로 상태, 텔레포트 중심 이동, 중단과 복귀 흐름을 유지해야 한다. 불과 연기의 형태나 연출을 새로 개선하는 작업은 포함하지 않는다.

**→ FR-010.** 변경 항목은 실제 화면으로 하나씩 제시하고 승인, 수정 요청, 미검토 상태를 구분해 기록해야 한다. 사용자가 이미 승인한 개선 방향을 결과 외관 승인으로 확대 해석해서는 안 된다.

**→ FR-011.** 구현 후 검증은 프로젝트 헌법 1.3.0의 실제 실행 영상, 게임 소리 분리, 화질, 재생 확인 및 대체 자료 규칙을 따라야 한다. 대표 자료는 사용자가 바로 열 수 있어야 하며 실제 기기와 수신 프로젝트 검증 여부를 따로 기록해야 한다.

**→ FR-012.** 제출 방식에 맞게 제작한 시각 자원과 필요한 재질을 전달할 수 있어야 한다. 외부 참고 자료와 포함 자원의 출처 및 재배포 조건을 구분해 기록하고 검증 원본은 제출 자원에 포함하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

**→ SC-001.** 착수 시 목록화한 실내 문, 큰 창문과 엘리베이터 출입구 문짝 및 프레임 배치의 100%에서 적용 및 접합부 확인을 마치며, 정면, 사선, 낮은 시점에서 관통과 의도하지 않은 배경 노출 0건을 확인한다. 엘리베이터 문짝 4개는 실내 문 17개와 별도 집계해 누락을 막는다. FR-001~003.

**→ SC-002.** 콘텐츠 3의 엘리베이터 2곳에서 중복 출입구 노출 0건, 계단실 4곳에서 상부 연결이 벽과 천장으로 막힌 사례 0건을 확인한다. FR-004~005.

**→ SC-003.** 대상 세 콘텐츠와 A/B 상황의 벽 하부 전수 확인에서 남은 걸레받이와 제거로 드러난 접합부 틈 0건을 확인한다. FR-007.

**→ SC-004.** 문과 창문 외형, 대피 경로 구조, 조명, 걸레받이 제거의 4개 검토 항목 각각에 실제 전후 자료와 사용자 승인 결과가 있다. 하나라도 미승인 또는 수정 요청 상태면 전체 외관 완료로 표시하지 않는다. FR-001~007, FR-010.

**→ SC-005.** 세 체험의 진입부터 결과와 메뉴 복귀까지 기존 핵심 진행 3개가 통과한다. 경로 체험은 직접 안전한 계단 선택과 막힌 계단에서 우회가 모두 통과하고, 중단 후 계속 및 메뉴 복귀에서 변경으로 생긴 진행 불능 0건을 확인한다. FR-009.

**→ SC-006.** 인물 교체, 바닥 재질과 무늬 비율 변경, 콘텐츠 2의 새 가구 배치 0건을 확인한다. FR-008.

**→ SC-007.** 변경 결과의 실제 실행 자료와 검증 기록을 제공한다. 영상은 1920×1080 이상, 30fps 이상과 게임 소리 분리 및 재생 확인을 충족하거나, 충족하지 못한 기준 각각의 사유와 대체 자료 및 한계를 기록한다. 미확인 환경을 검증 완료로 표시한 사례 0건을 유지한다. FR-011~012.

## Assumptions

**→ 사용자 확정 사항.** 실제 학교 외형을 기준으로 문과 창문을 개선하고, 켜 둔 Blender를 활용해 직접 제작한다. 콘텐츠 3의 엘리베이터와 문 겹침 및 계단 막힘을 수정한다. 조명을 개선하고 전체 콘텐츠의 걸레받이를 제거한다. 제작 도구 선택은 사용자가 정한 작업 제약이며 구체적인 자원 구조와 제작 절차는 후속 계획에서 정한다.

**→ 유지 결정.** 인물과 바닥 재질은 우선 유지한다. 콘텐츠 2는 빈방 형태를 유지한다. 걸레받이를 얇게 하거나 다른 색으로 남기는 AI 제안은 채택되지 않았으며 제거가 최종 결정이다.

**→ 아직 확정하지 않은 사항.** 문과 창문의 정확한 색과 제품 형태, 조명의 최종 수치는 사용자가 지정하지 않았다. 기존 공간과 문 용도에 맞는 시안을 실제 화면으로 제시하며, 특정 색이나 치수를 이미 승인한 것으로 취급하지 않는다.

**→ 검토 기준.** 문과 창문 개선은 새 창문을 모든 공간에 추가한다는 뜻이 아니다. 현재 있는 요소를 대상으로 하며 구조 오류를 고치는 데 필요한 인접 벽과 천장만 함께 보완한다. 창문 너머의 외부 풍경과 학교 외부 배경은 새로 제작하지 않는다. 유리 표현을 개선하기 위해 별도의 외부 공간 제작을 필수 조건으로 삼지 않는다.

**→ 의존성과 검증 범위.** 기존 세 콘텐츠와 공용 진행 기능이 기준이다. 현재 실행 가능한 제작 환경의 화면으로 외관을 검토하고 실제 VR의 입체감, 편안함, 성능과 지정 제출 프로젝트 수용 검증은 별도로 기록한다. 기존 기능이나 학습 효과를 검증했다는 과거 결과를 새 외관 승인으로 재사용하지 않는다.

**→ 사실과 증거.** 대화 중 현재 Unity 씬에서 엘리베이터 뒤 교실 문, 계단 끝의 벽, 단순한 문과 창문, 조명 얼룩을 확인했다. 검토용 편집 화면은 `Artifacts/Validation/visual-review-01-lighting.png`부터 `visual-review-05-smoke-room.png`에 있다. 이는 구현 전 편집 화면이며 실제 실행 검증이나 변경 후 승인 자료가 아니다. 후속 구현 증거는 헌법의 공통 경로에 새로 보관한다.
