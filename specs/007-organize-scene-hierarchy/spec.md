# Feature Specification: 씬 전체 하이라키와 영어 명명 정리

**Feature Branch**: 기존 `main` 유지. 이번 명세 작성에서 브랜치 생성 없음.

**Feature Directory**: `specs/007-organize-scene-hierarchy`

**Created**: 2026-11-17

**Status**: Draft

**Input**: 사용자 요청: “하이라키 전체랑 명명도 정리했으면 좋겠어.” 후속 선택에서 영어 중심 명명과 구역 및 역할을 함께 사용하는 배경 분류를 확정했다. 기존 체험의 배치와 동작을 보존하면서 편집할 대상을 쉽게 찾는 것이 목적이다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 편집할 대상을 구역과 역할로 찾기 (Priority: P1)

제작자는 공용 기능과 각 체험을 구분하고, 원하는 공간의 배경, 조작 대상, 캐릭터, 이동 지점과 버튼 표시 위치를 역할별로 찾는다.

**Why this priority**: 반복 부품이 한 목록에 길게 나열된 현재 구조를 정리하는 것이 핵심이다.

**Independent Test**: 실행하지 않은 씬에서 비상벨, 주변 인물, 연기 효과, 두 대피 시나리오의 계단과 이동 지점, 선택지 표시 위치를 해당 구역과 역할 그룹에서 찾는다.

**Acceptance Scenarios**:

1. **Given** 편집 상태의 씬, **When** 최상위 그룹을 확인하면, **Then** 공용 기능과 체험 공간이 구분되고 체험 선택 공간과 세 체험을 각각 찾을 수 있다.
2. **Given** 어느 체험을 편집하는 상태, **When** 하위 그룹을 펼치면, **Then** 존재하는 실행 관리, 배경, 조작 대상, 캐릭터, 효과, 이동 지점과 위치 기준점이 역할별로 구분되고 빈 분류 그룹은 없다.
3. **Given** 대피 경로 체험의 두 시나리오, **When** 배경을 펼치면, **Then** 복도, 교실, 계단, 엘리베이터를 공간 단위로 구분하고 각 공간 안에서 구조물, 문, 창문, 조명과 장식 부품을 역할별로 찾을 수 있다. 두 복도를 가진 시나리오는 복도별 구분도 유지한다.
4. **Given** 같은 역할의 반복 부품, **When** 하나를 선택하면, **Then** 같은 부모 아래에서 이름으로 다른 부품과 구분할 수 있다.

### User Story 2 - 영어 이름으로 용도 파악하기 (Priority: P1)

제작자는 프로젝트가 직접 관리하는 오브젝트의 영어 이름으로 역할을 파악한다. 체험자가 읽는 한국어 문구는 유지된다.

**Why this priority**: 의미가 모호한 이름과 한글, 영어가 혼재한 이름은 대상을 찾기 어렵게 한다.

**Independent Test**: 체험 선택, 설정, 다시하기 버튼과 시나리오, 계단, 위치 기준점 이름을 실제 용도 및 화면 문구와 비교한다.

**Acceptance Scenarios**:

1. **Given** 프로젝트 소유 정리 대상, **When** 이름을 확인하면, **Then** 공백 없는 영어 PascalCase를 사용하고 버튼은 `Button`, 텍스트는 `Text`, 위치 기준점은 `Anchor`로 끝난다. 같은 부모 아래 반복 부품은 `01`부터 시작하는 두 자리 이상의 번호로 구분한다.
2. **Given** `Content1`, `설정`, `다시 체험하기`, `선택 화면으로` 오브젝트, **When** 정리 후 확인하면, **Then** 각각 `FireNotificationButton`, `SettingsButton`, `RetryButton`, `ReturnToSelectionButton`처럼 실제 역할이 드러난다.
3. **Given** 대피 경로 체험의 `A`, `B`와 한글이 섞인 계단 이름, **When** 정리 후 확인하면, **Then** `ScenarioA`, `ScenarioB`, `Stairwell01`, `Stairwell02`로 구분된다.
4. **Given** 정리된 UI, **When** 체험자가 화면을 보면, **Then** 한국어 안내, 버튼 문구와 교육 내용은 정리 전과 같다.

### User Story 3 - 공용 UI를 찾고 기존 체험 유지하기 (Priority: P1)

제작자는 공용 UI 그룹에서 체험 선택, 체험 중 안내, 일시정지, 설정, 확인창, 결과와 바닥 버튼을 찾는다. 체험자는 기존 순서와 조작으로 세 체험을 이용한다.

**Why this priority**: 정리 때문에 공용 기능이 중복되거나 기존 연결이 깨져서는 안 된다.

**Independent Test**: 공용 UI의 각 역할을 찾고 세 체험에서 기존 선택, 진행, 일시정지, 재개, 결과와 복귀를 확인한다.

**Acceptance Scenarios**:

1. **Given** 공용 UI 그룹, **When** 펼치면, **Then** 화면 UI와 바닥 버튼을 각각 찾을 수 있고 화면 UI 안에서 체험 선택, 체험 중 안내, 일시정지, 설정, 확인창과 결과를 구분할 수 있다.
2. **Given** 정리 전후의 같은 체험 단계, **When** 같은 위치와 방향에서 관찰하면, **Then** 배경, 캐릭터, 조작 대상과 UI의 위치, 크기, 방향, 표시 순서가 같다.
3. **Given** 정리된 씬, **When** 세 체험의 주요 경로를 수행하면, **Then** 선택과 진행이 한 번씩 실행되고 일시정지, 설정, 재개, 결과와 선택 화면 복귀가 기존대로 작동한다.
4. **Given** 저장 후 다시 연 씬, **When** 편집 상태와 실행 상태를 확인하면, **Then** 구조와 이름, 기존 표시 및 숨김 규칙과 체험 전환이 보존된다.

### Edge Cases

- 반복 부품 이름의 고유성은 같은 부모 아래에서 판단한다. 씬 전체 고유 이름은 강제하지 않는다.
- XR 리그 내부, 캐릭터 뼈대 및 애니메이션 연결 이름, 외부 패키지 프리팹 내부, 자동 생성 텍스트 보조 오브젝트는 보호 대상으로 보존한다.
- UI 분류 변경으로 레이아웃, 가림, 표시 순서나 입력 순서가 달라져서는 안 된다.
- 체험과 시나리오 전체를 켜고 끄는 경계를 보존한다. 편집 편의를 위해 숨겨진 패널을 모두 켜서 저장하지 않는다.
- 이동 지점이나 위치 기준점의 표시 이름이 바뀌어도 콘텐츠, 시나리오와 지점 식별자의 의미와 연결은 유지한다.
- 시각 부품과 조작 기능이 함께 있는 대상은 기능 연결을 보존하고 조작 대상으로 찾을 수 있는 분류를 우선한다.
- 다른 사용자 변경이나 저장하지 않은 씬 변경을 발견하면 이를 덮어쓰지 않고 작업 대상 변경과 구분한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 현재 사용하는 `FireNotification` 씬 전체의 프로젝트 관리 대상을 정리해야 한다. 체험 선택 공간, 화재 사실 알리기, 연기 속 대피, 대피 경로 판단과 공용 기능을 포함한다.
- **FR-002**: 공용 기능에서 플레이어, 체험 전환, 입력, 실행 상태 관리, 머리 추적, 음성, 조명과 UI를 역할별로 찾을 수 있어야 한다.
- **FR-003**: 체험별로 존재하는 실행 관리, 배경, 조작 대상, 캐릭터, 효과, 이동 지점과 위치 기준점을 분류해야 하며 빈 그룹은 추가하지 않아야 한다.
- **FR-004**: 배경은 구역을 먼저 구분하고 각 구역 안에서 역할별로 묶어야 한다. 반복 부품 전체를 구역 구분 없이 한 목록에 나열해서는 안 된다.
- **FR-005**: 공용 화면 UI와 바닥 버튼은 공용 UI 분류에서 찾을 수 있어야 하며 체험별 중복 UI를 추가해서는 안 된다.
- **FR-006**: 정리 대상은 Story 2의 영어 명명 규칙을 따라야 한다. 모호한 이름은 실제 역할을 나타내도록 바꾸고 같은 부모 아래 반복 부품은 이름으로 구분해야 한다.
- **FR-007**: 한국어 화면 문구, 교육 내용, 선택 결과, 진행 순서와 기존 조작 방식을 보존해야 한다.
- **FR-008**: 배치, 외형, 표시 순서, 조작 범위와 조명 결과를 보존해야 한다. 화면을 따라오는 UI와 공간에 배치되는 바닥 버튼의 기존 표시 방식도 보존해야 한다.
- **FR-009**: 오브젝트 연결, 버튼 동작, 콘텐츠 등록, 식별자와 체험 및 시나리오 전환 경계를 보존해야 한다. 누락되거나 의도와 다른 대상으로 바뀐 연결이 없어야 한다.
- **FR-010**: 저장 상태와 실행 중의 기존 활성화 및 비활성화 규칙을 보존해야 하며 씬을 다시 열어도 정리된 구조와 이름이 유지되어야 한다.
- **FR-011**: 보호 대상 내부 구조와 이름을 보존해야 한다. 프로젝트 소유 프리팹을 정리할 때는 연결된 인스턴스에서도 일관된 의미를 가져야 한다.
- **FR-012**: 정리 전후 주요 경로의 비교 검증과 주요 편집 경로 안내를 제공해야 한다. 검증 자료는 프로젝트 헌법의 실행 영상, 소리 분리, 보관과 미검증 범위 보고 기준을 따라야 한다.

### Key Entities

- **공용 기능 그룹**: 모든 체험이 공유하며 특정 체험의 활성 상태에 종속되지 않는 기능 분류다.
- **체험 공간 및 시나리오 구역**: 독립 체험과 대피 경로 체험의 두 상황을 구분하는 편집 단위다.
- **역할 그룹**: 같은 구역 안에서 배경, 조작 대상, 효과, 이동 지점과 위치 기준점 등의 용도를 구분한다.
- **보호 대상**: 외부 연결이나 자동 생성 규칙 때문에 내부 이름과 구조를 유지해야 하는 요소다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 제작자는 전역 이름 검색 없이 구역과 역할 그룹을 따라 비상벨, 두 주변 인물, 연기 효과, 두 시나리오 각각의 두 계단 및 이동 지점 그룹, 각 체험의 바닥 버튼 위치 그룹을 모두 찾을 수 있다. 확인 대상 누락은 0개다.
- **SC-002**: 보호 대상을 제외한 정리 대상의 이름 규칙 준수율은 100%이며 같은 부모 아래 구분되지 않는 중복 이름은 0개다.
- **SC-003**: 체험 선택과 세 체험의 적용 가능한 주요 경로에서 정리로 발생한 진입, 선택, 진행, 일시정지, 재개, 설정, 결과와 복귀 실패는 0건이다. 적용 불가능한 경로는 사유를 기록한다.
- **SC-004**: 정리 전후 배치, 문구, 표시 순서, 조작 결과와 기존 연결의 의도하지 않은 차이는 0건이며 씬을 저장하고 다시 열어도 동일하다.
- **SC-005**: 실행 확인 결과, 대표 시각 자료와 주요 편집 경로 안내를 제공한다. 수행하지 않은 환경과 소리 확인 항목을 검증 완료로 표시한 사례는 0건이다.

## Assumptions

- 사용자 확정 사항은 전체 하이라키와 이름 정리, 영어 중심 명명, 구역과 역할을 함께 사용하는 배경 분류다. 구체적인 그룹명과 배치 방식은 후속 계획에서 요구사항에 맞춰 정한다.
- 기본 대상은 `Assets/_02LWS/Scenes/FireNotification.unity`와 연결된 프로젝트 소유 프리팹이다. 사용하지 않는 `ContentMenu.unity`, Project 창 폴더명, 스크립트 파일명과 외부 패키지 원본은 제외한다.
- UI 미리보기 도구, 새 교육 기능, 화면 디자인 변경과 새 외부 의존성은 추가하지 않는다. 숨겨진 패널 확인을 위한 별도 도구도 이번 범위에서 제외한다.
- 기존 공용 UI와 바닥 버튼 기능 및 세 체험의 등록 상태를 기준으로 정리한다. 보호 대상 목록은 후속 계획에서 실제 연결과 기존 검사 조건을 확인해 확정한다.
- 검증은 실제 수행한 환경에 한정한다. Editor 확인으로 실제 Quest 기기의 동작, 성능이나 착용감을 검증했다고 간주하지 않는다.
