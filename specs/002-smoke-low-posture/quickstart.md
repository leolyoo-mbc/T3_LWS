# Quickstart validation: 연기 속에서 자세 낮추기

**현재 상태**: 계획만 작성됐다. 새 연기 체험·검증 도구·음성은 아직 구현하지 않았다. 아래는 구현 후 실행할 검증 절차이며 실행 결과가 아니다.

## 준비

Unity 6000.3.26f1과 현재 Packages/manifest.json·packages-lock.json 구성을 사용한다. 패키지를 임의 업그레이드하지 않는다. Unity Hub에서 프로젝트를 열고 Assets/_02LWS/Scenes/FireNotification.unity를 연다. Console 컴파일 오류 0건을 확인한다.

Quest 검증에는 Android Build Support/SDK/NDK/JDK, 기존 OpenXR/Meta Quest 설정, Quest 2와 컨트롤러, 안전하게 숙일 수 있는 공간이 필요하다. 손 추적·마이크·네트워크는 필요 없다. 기기가 없으면 Q7/Q8/Q9의 관련 결과를 미검증으로 남긴다.

참조: [데이터/상태](data-model.md), [공통 연결 계약](contracts/content-integration.md), [화면/대본](contracts/experience-ui.md). PC 높이 주입/시뮬레이터 성공은 실기기 자세 검증으로 기록하지 않는다.

## Q1. 판정·초기 기준 Editor 입력 주입 검증 — SC-002

구현 후 씬을 Play Mode로 실행하고 T027의 Editor 전용 입력 경로를 사용한다. 각 조건은 새 실행에서 준비 선택·원리 안내 완료·연습 진입까지 진행한 다음 높이/시간/추적/차단 입력을 순서대로 넣어 확인한다. 준비 전 조건은 준비 선택 없이 수행한다. 아래 조건별 입력 순서·기대/실제 결과·증거를 SmokePostureDetection.md에 기록한다. 새 자동 테스트 코드나 Test Runner XML을 요구하지 않는다. 기존 관련 자동 테스트가 있으면 추가 실행해 결과를 별도 기록한다.

| 입력 | 예상 |
|---|---|
| 준비 전 낮은 샘플/대기 | 기준 확정·완료 0건 |
| 유효 추적에서 준비 선택 | 선택 순간 높이만 저장 |
| 시작 높이 1.2/1.6/1.9 m(합성 입력)에서 각각 기립·낮춤·재기립 | 상대 판정. 기립으로 완료 0건 |
| 낮춤 1.99초 후 재기립 | 미완료, 유지 0 |
| 낮춤 연속 2초 | 완료 이벤트 1회, 이후 기립/샘플 반복에도 완료 유지·중복 0건 |
| 관찰 중 숙임 후 Practice 진입 | 진입 전 시간 합산 안 됨 |
| 경계 부근 흔들림 | 설정된 진입/해제 경계대로 판정, 경계값 포함/초과 비교 검증 |
| NaN/무효 설정/Position 비트 없는 추적 | 판정 보류, 완료 0건 |

합성 높이는 검증 데이터이며 사용자 지원 신장 범위나 교육 안전 높이가 아니다.

## Q2. 연기·제자리 표현 — FR-002/003/005/008, SC-003

Play에서 새 콘텐츠에 진입한다. 초기에 위로 모여 천장 부근으로 퍼지는 모습을 관찰한다. 연습 진입 뒤 30초 기다리고 숙이기/일어서기를 반복한다. 입자는 움직이고 층 경계는 공간에 고정돼야 한다. 성공해도 연기 전체가 사라지지 않아야 한다.

텔레포트·연속 이동·강제 회전/카메라 이동이 연습 중 작동하지 않는지 확인한다. pending 텔레포트를 가진 채 진입/모달 열기를 시험한다. 대기 중 시간 초과·점수 차감·더 낮아지는 연기·실패 처벌은 없어야 한다. 메뉴↔공간 초기 배치는 연습 중 탈출 이동과 구분한다.

## Q3. 필수 안내·읽기 — FR-004/010, SC-003

기본 자막 켬으로 한국어 음성/자막을 처음부터 끝까지 대조한다. 흡입 감소 목적, 아래로 퍼질 수 있음, 낮은 자세만으로 안전하지 않음, 대피 가능한 경우 낮은 자세로 신속히 이동, 제자리 연습과 실제 탈출의 구분이 모두 있어야 한다. ‘안전 확보/탈출 성공/공기 안전 보장’ 문구는 0건이어야 한다.

자막 끄기·음성 0·글자 150% 각각에서 조작/추적/인식/중단 안내가 남고 잘림·누락 글리프·버튼 겹침이 없는지 확인한다. 서기·숙이기 모두 읽을 수 있어야 한다. 실제 Quest 읽기는 Q7에서 별도 기록한다.

## Q4. 실제 인식 피드백 — SC-002/004

Editor 샘플 주입으로 전이를 확인한 뒤 Quest에서 준비 선택 → 편한 숙임 → 일어서기를 시험한다. 편한 숙임 범위에서 인식되지 않으면 미합격으로 기록하고 판정 제안값을 조정한다. 사용자를 더 깊이 숙이도록 압박하지 않는다.

개발 빌드의 검증 표시를 켜고 실제 head 입력으로 측정한다. 시작은 Practice에서 유효한 머리 위치 샘플이 낮은 자세 진입 경계에 처음 도달한 순간이며, 신체 움직임 시작이나 2초 완료 시점이 아니다. 끝은 인식 피드백이 표시된 첫 프레임이다. 입력 경계 통과 표식과 인식 피드백을 같은 화면 녹화에서 식별하고, 실행 번호·프레임 번호·동일한 단조 증가 시계의 시각으로 대응을 확인한다.

녹화의 두 표식이 처음 나타난 프레임 사이 시간을 D, 해당 구간의 최대 프레임 간격을 G로 기록한다. 시작/끝 프레임의 양자화 오차를 보수적으로 포함해 D+2G가 1초 이하여야 통과다. 안정된 F fps라면 G=1/F로 계산한다. 가변 프레임 녹화는 실제 프레임 시각을 사용한다. 표식은 원래 입력/표시 처리 프레임에 갱신해야 하며 표식 지연·프레임 누락 등으로 오차 상한을 확인할 수 없으면 미검증으로 남긴다. 센서 자체 지연을 포함한 신체 움직임 전체 지연이라고 주장하지 않는다.

검증 표시는 Editor 또는 개발 빌드에서 명시적으로 켠 경우만 제공하고 정상 UI를 가리지 않게 한다. Quest에서는 실제 입력 관찰만 가능하며 자세/시간 주입·완료 건너뛰기를 제공하지 않는다. 측정값은 실행 메모리에서만 사용해 종료 시 폐기한다. 기록에는 시각/프레임 차이·오차·결과만 남기고 실제 머리 높이·궤적을 장기 저장하지 않는다.

## Q5. 중단·추적·동시 입력 — FR-009, SC-002/006

각각 시작 확인/원리 안내/자세 연습/완료 안내에서 메뉴를 열고 복귀한다. 음성·연기는 pause 중 정지하고 뒤쪽 입력은 무시돼야 한다. 새로 2초를 확인해야 할 미완료 상태와 이미 인정된 완료를 구분한다.

낮춤 1.9초 뒤 일반 pause, 앱 pause/헤드셋 벗기, 위치 추적 상실을 각각 시험한다. 복구 후 이전 시간을 이어서 완료하면 실패다. 판정 가능한 새 연속 2초가 필요하다. 완료 인정과 같은 프레임에 이탈/추적 상실/일시정지를 주입하면 차단이 우선해야 한다.

XR 추적 원점/모드 변경·Origin 불연속 이동은 기준을 폐기하고 새 준비를 요구해야 한다. UI 재정렬만으로 기준을 바꾸면 실패다. 추적 관련 실제 OS 동작은 Quest에서 검증하고 Editor 가짜 신호 결과와 구분한다.

## Q6. 정상 반복·재진입 — SC-001/006

준비 → 관찰 → 자세 연습 → 한계 안내 → 결과 → 메뉴를 3회 연속 진행한다. 매번 새 기준·시간·완료 상태를 사용해야 한다. 네 단계 모두에서 중단 후 재진입도 확인한다. 이전 콜백이 새 실행을 완료하거나 이전 음성이 겹치면 실패다. 재시작도 새 준비부터 시작하고 설정은 유지한다.

## Q7. 콘텐츠 1 회귀·Quest 실행 — FR-001/002

콘텐츠 1 전체(큰소리 선택→반응→상황 복원→직접 벨→경보→완료)를 진행한다. 연기 체험에 들어갔다 나온 뒤 다시 진행한다. 두 콘텐츠의 메뉴·설정·pause·재시작·복귀·결과가 각 활성 콘텐츠에 적용돼야 한다. 콘텐츠 1 이동과 벨 직접 누름을 유지한다.

기존 Android 설정을 확인하고 File → Build Profiles에서 Android 빌드·Quest 설치·단독 실행한다. 비행기 모드의 최초 실행에서 음성/자막/연기가 제공되고 컨트롤러 레이/트리거·숙임·중단이 작동해야 한다. 서기/숙이기에서 표시 거리·150% 글자·중단 버튼 도달성을 확인한다. 실제 장치가 없거나 APK를 만들지 않았다면 PASS를 기록하지 않는다.

## Q8. 교육 효과·성능 — SC-005 및 제품 목표

체험자 5명에게 종료 뒤 몸을 낮추는 이유와 낮은 곳도 완전히 안전하지 않은 이유를 자기 말로 설명하도록 한다. 4명 이상이 두 내용을 모두 설명해야 SC-005 충족이다. 개인정보/신체 수치 없이 익명 시험 번호·설명 요지·결과만 기록한다. 실제 참여 없이 달성했다고 쓰지 않는다.

Quest 프로파일링에서 양안 연기 표현, 투명 입자 중첩, CPU/GPU 프레임 시간을 확인한다. 72 Hz 설정의 13.9 ms는 AI 제안 비교 기준이며 확정 합격 수치가 아니다. 입자 수/크기/중첩과 해상도 설정을 기록해 조정 전후를 비교한다. 실제 기기 결과가 없으면 성능 미검증이다.

## Q9. Export·수신 프로젝트 — FR-013 및 제출 조건

신규 음성/재질/텍스처/폰트/셰이더의 파일·.meta·권리 기록을 확인한다. 저장된 씬/프리팹의 프로젝트 참조가 Assets/_02LWS 밖을 가리키지 않는지 다시 검사한다. 로컬 저장/네트워크 전송·새 마이크 입력이 추가되지 않았는지도 확인한다.

Assets/_02LWS를 선택해 최신 소스로 unitypackage를 Export한다. 별도 수신 Unity 프로젝트에 기록한 UPM/XR 조건을 갖추고 Import한 뒤 Console 오류 0건과 두 콘텐츠 전체 진행을 확인한다. ProjectSettings/UPM이 package에 자동 전달된다고 가정하지 않는다. 수신 프로젝트가 지정되면 해당 환경에서도 재검증한다.

## 기록

각 결과에 소스 commit 또는 변경 상태, Unity/패키지 버전, 씬, 기기/입력 방식, 절차 ID, 기대/실제 결과, 증거 파일, 미검증 이유를 남긴다. Editor 입력 주입·Play Mode·Quest·Import·교육 효과 결과를 구분하고 기존 자동 테스트를 실행했다면 별도로 기록한다. 기존 콘텐츠 1의 과거 PASS를 새 연기 체험의 PASS로 복사하지 않는다.

## Q11. 체험 UI 시야 보존 — FR-019 / SC-010

두 콘텐츠의 진입·설명·선택·다음·직접 벨·자세 연습·완료를 실제 순서대로 실행한다. 체험 안내는 아래쪽에 있으며 정면에 고정 대형 배경이 없어야 한다. 빈 상태/자막 행은 높이0이고 내용/버튼이 모두 없으면 배경이 꺼져야 한다. 자막 끄기와 글자150%를 바꿔 조작/추적 안내·전체 선택 문구·자막이 잘리지 않는지 확인한다. 서기/숙이기와 메뉴/모달 복귀 시 하단 기준·클릭 차단을 확인한다. MP4·주요 화면·글자 영역 검사를 함께 남긴다. Editor 합성 입력과 실제 Quest 읽기/편안함은 구분한다.
