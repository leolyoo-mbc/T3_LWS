## Clarifications

### Session 2026-11-13

- Q: ‘연기 속 대피’ 공간은 현재 방 모양을 유지하면서 다듬을까, 방 구조부터 바꿀까? → A: 현재 방 형태를 유지하고 문틀·천장등·걸레받이와 문 너머 공간을 보완한다. 실제 화면으로 상자 같은 인상이 줄었는지 확인한다.
- Q: 이번 비주얼 수정은 Unity 실행 화면을 보고 승인할까, VR 기기에서 확인한 뒤 승인할까? → A: Unity 실행 화면으로 외관을 승인한다. 실제 VR 기기의 입체감·편안함·성능 검증은 별도 항목으로 남기며 이번 외관 작업 완료의 필수 조건으로 삼지 않는다.

- Q: 조명 구성을 복잡하게 만들지 않으려면 어떻게 정리할까? → A: 콘텐츠별 렌더 설정 전환과 새 전환 컴포넌트를 없애고 기존 공용 설정 하나를 사용한다. 천장등과 화재 불빛은 각 공간에 두며 진입·종료 때 렌더 설정을 교체·복원하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 완성된 실내 복도에서 화재 사실 알리기 (Priority: P1)

체험자는 기존 복도에서 알리기와 비상벨 체험을 진행하며 위·뒤를 둘러봐도 공간이 끊기지 않는 실제 건물 내부를 경험한다.

**Why this priority**: 사용자는 복도 구조는 괜찮으며 벽·문과 천장·뒤쪽 마감이 필요하다고 명시했다.

**Independent Test**: 이 체험만 실행해 기존 진입·이동 위치에서 둘러보고 알리기부터 비상벨 완료까지 진행한다.

**Acceptance Scenarios**:

1. **Given** 기존 복도와 체험 동선, **When** 변경 후 같은 위치에서 관찰하면, **Then** 주요 구조·동선은 유지되고 벽·문에 표면 재질과 건축 마감이 보인다.
2. **Given** 진입 또는 비상벨 접근 위치, **When** 위·뒤를 보면, **Then** 천장과 뒤쪽 마감이 이어지고 제작 누락으로 빈 배경이나 다른 체험 공간이 노출되지 않는다.
3. **Given** 실내를 관찰하는 상태, **When** 조명과 접합부를 보면, **Then** 천장등과 주변 밝기·그림자가 일관되고 문틀·걸레받이 등 접합부가 마감되어 있다.
4. **Given** 보완된 복도, **When** 알리기·상황 복원·비상벨·완료·메뉴 복귀를 진행하면, **Then** 기존 입력과 진행이 작동하며 새 환경이 동선이나 필수 안내를 가리지 않는다.

---

### User Story 2 - 문 너머 화재와 빽빽한 연기 관찰 (Priority: P1)

체험자는 문 너머 화재를 보고 연기의 원인을 이해하며, 문 위쪽으로 들어와 천장 아래 퍼지는 연기를 관찰한다. 연기는 듬성듬성한 조각보다 서로 이어진 층으로 보인다.

**Why this priority**: 사용자가 정정한 핵심은 매캐한 색감이 아닌 빽빽함이며, 화재 없이 연기만 발생하는 상황도 어색하다고 지적했다.

**Independent Test**: 자세 판정과 별개로 원리 안내·연습 단계의 화재와 연기를 관찰하고 같은 조건의 변경 전후 화면을 비교한다.

**Acceptance Scenarios**:

1. **Given** 연출 시작 상태, **When** 문 쪽을 보면, **Then** 불은 사용자 방 안이 아닌 문 너머에 있고 불꽃 일부와 흔들리는 불빛이 보인다.
2. **Given** 문 너머 화재, **When** 연기가 유입되면, **Then** 문 위쪽의 유입과 천장 부근으로 퍼지는 흐름이 공간적으로 이어진다.
3. **Given** 위치·방향·단계·단계 시작 후 경과시간을 맞춘 전후 화면, **When** 연기층을 비교하면, **Then** 큰 빈틈과 배경이 선명하게 드러나는 구간이 줄고 사용자가 빽빽함 개선을 승인한다.
4. **Given** 연습 단계, **When** 자세를 낮추거나 완료하면, **Then** 연기가 갑자기 사라지지 않고 낮은 위치가 항상 안전한 청정 구역처럼 표현되지 않는다.

---

### User Story 3 - 상자 같은 공간 인상 개선 (Priority: P2)

체험자는 ‘연기 속 대피’에서 단순한 상자보다 실제 건물 안에 있다는 인상을 받는다. 제작자는 현실적인 표면·빛과 문 너머 공간 연결을 실제 화면으로 판단한다.

**Why this priority**: 사용자가 해당 체험 공간을 큐브 안처럼 느낀다고 확인했고, 현재 방 형태를 유지하면서 문틀·천장등·걸레받이와 문 너머 공간을 보완하는 방향을 선택했다.

**Independent Test**: 연기가 실내를 덮기 전과 진행 중의 환경을 각각 관찰하고 사용자에게 인상 개선 여부를 확인한다.

**Acceptance Scenarios**:

1. **Given** 연기가 가리기 전 실내, **When** 사방·위·아래를 살펴보면, **Then** 재질·조명과 문 너머 공간이 건물 내부로 읽히며 사용자가 상자 같은 인상 개선을 승인한다.
2. **Given** 문 너머 화재 공간, **When** 비스듬히 문을 보면, **Then** 연결된 바닥·벽이 보이고 빈 배경이나 미완성 뒷면이 드러나지 않는다.
3. **Given** 세부 디자인을 검토할 때, **When** 요소를 채택하면, **Then** 사용자 승인과 적용 대상을 기록하고 미승인 제안을 확정 사항으로 취급하지 않는다.

---

### User Story 4 - 실제 화면으로 개선 결과 판단 (Priority: P2)

제작자는 실행 자료로 결과를 보고 일반 화면과 실제 헤드셋 검증을 구분한다.

**Why this priority**: 사용자가 적용 결과를 보고 싶다고 했으며 빽빽함을 어떻게 확인할지도 직접 물었다.

**Independent Test**: 두 체험의 실행 자료와 검증 기록을 열어 비교 조건·실제 결과·승인·미검증 환경을 확인한다.

**Acceptance Scenarios**:

1. **Given** 개선 결과, **When** 검토 자료를 열면, **Then** 두 체험의 진입·둘러보기·핵심 동작·결과를 실제 실행 영상으로 확인한다. 녹화 불가 시 사유·한계를 적은 단계별 실행 화면 자료가 있다.
2. **Given** 일반 화면만 확인한 결과, **When** 완료 기록을 읽으면, **Then** 헤드셋 입체감·편안함·성능은 미검증으로 구분되고 사용자 미승인을 최종 시각 승인으로 표시하지 않는다.
3. **Given** Unity 실행 화면으로 사용자가 외관을 승인하고 나머지 이번 작업 조건을 충족한 상태, **When** 완료 여부를 판단하면, **Then** 실제 VR 기기 검증을 별도 미완료 항목으로 남긴 채 이번 외관 작업을 완료할 수 있다. 이를 전체 앱의 VR 검증 완료나 제출 승인으로 표시하지 않는다.

### Edge Cases

- 정면 외 방향: 위·뒤·문 옆에서 빈 배경, 면 뒷면, 접합부 틈과 다른 체험 공간이 드러나지 않아야 한다.
- 비상벨 접근과 낮은 자세: 마감이 머리 위치·손 상호작용·필수 안내를 가리거나 기존 접근을 막지 않아야 한다.
- 짙어진 연기: 필수 안내와 중단 조작은 사용 가능해야 하며, 연습 중 연기층이 내려와 더 깊이 숙이도록 압박하지 않아야 한다.
- 문 너머 관찰: 불꽃이 방 안에서 나거나 벽을 통과하는 것처럼 보이지 않고 연기 유입 위치와 연결되어야 한다.
- 일시정지·추적 상실·재진입: 화재·불빛·연기는 기존 중단·재개·초기화 규칙을 따르며 다른 체험에 남지 않아야 한다.
- 공유 자산: 한 콘텐츠의 재질 변경이 다른 콘텐츠에 의도하지 않은 외관 변경을 일으키지 않아야 한다.
- 기기·녹화 제약: 확인하지 못한 외관·편안함·성능을 완료로 기록하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 대상은 두 체험의 환경·화재·연기 외관이다. 같은 장소로 통일하거나 학교 배경을 강제하지 않아야 한다.
- **FR-002**: ‘화재 사실 알리기’는 기존 복도 주요 구조·동선을 유지하며 벽·문 재질과 마감을 개선해야 한다.
- **FR-003**: 해당 복도는 천장·뒤쪽을 마감하여 기존 진입·이동 위치에서 둘러봐도 제작 누락으로 공간 밖이 노출되지 않아야 한다.
- **FR-004**: 해당 복도는 천장등과 일관된 실내 조명, 문틀·걸레받이 등 접합부 마감을 포함해야 한다.
- **FR-005**: ‘연기 속 대피’는 현재 방 형태를 유지하고 문틀·천장등·걸레받이와 문 너머 공간을 보완해야 한다. 현실적인 재질·조명과 공간 연결로 큐브 같은 인상을 개선하고 실제 화면으로 사용자 승인을 받아야 한다. 기존 방 외곽 모양·크기·진입 위치는 유지한다. 현재 문이 없는 벽에 문 너머 화재를 보여줄 새 개구부와 연결 공간을 추가하는 작업은 포함하되 새로운 이동 경로나 문 조작은 추가하지 않는다.
- **FR-006**: 이 체험의 화재는 문 너머 다른 공간에 있어야 하며 사용자 위치에서 불꽃 일부·흔들리는 불빛이 보여야 한다.
- **FR-007**: 연기는 문 위쪽에서 들어와 천장 부근으로 퍼져야 한다. 방 안의 독립된 상승 연출이 다른 발생 원인을 암시하지 않아야 한다.
- **FR-008**: 연기층은 변경 전보다 큰 빈틈이 줄고 빽빽해 보여야 한다. 어두운 색이나 매캐한 인상만으로 충족했다고 간주하지 않아야 한다.
- **FR-009**: 빽빽함은 위치·방향·단계·경과시간을 맞춘 전후 자료로 비교하고 사용자 승인을 받아야 한다. 특정 입자 크기·연출 기법을 고정하거나 측정 없이 저비용이라고 단정하지 않아야 한다.
- **FR-010**: 연습 중 연기층 높이는 일정하게 유지하고 낮은 자세에서도 연기는 남아 있어야 한다. 낮은 자세만으로 안전해지지 않는다는 기존 안내와 모순되는 안전지대 표현을 만들지 않아야 한다.
- **FR-011**: 알리기·비상벨·준비 완료·자세 인식·연속 2초 유지·중단·재개·완료·재진입을 유지하고 새 환경이 필수 조작·안내를 막지 않아야 한다.
- **FR-012**: 새 외부 환경 자산은 CC0 제공 자산을 사용하고 개별 출처·라이선스 근거·수정 여부를 확인할 수 있어야 한다. 실행 시 외부 다운로드를 요구하지 않아야 한다.
- **FR-013**: 채택한 환경 자산은 기존 제출용 콘텐츠에 포함 가능해야 하며 통합 프로젝트 전달 시 필수 자원이 빠지지 않아야 한다.
- **FR-014**: 구현 결과는 헌법에 따른 실제 실행 MP4로 기록해야 한다. 불가능하면 사유·대체 시각 자료·한계를 기록하고 정해진 로컬 경로에 보관하며 버전 관리·제출 자산에서 제외해야 한다.
- **FR-015**: 동일 조건의 변경 전후 실행 성능과 실제 기기 검증 여부를 기록해야 한다. 새 효과로 재현 가능한 멈춤·입력 지연이 생기면 미해결로 남기며 별도 합의 없이 새로운 수치 합격 기준을 확정하지 않아야 한다.
- **FR-016**: 이번 외관 승인은 Unity 실제 실행 화면을 기준으로 사용자가 결정해야 한다. 실제 VR 기기의 입체감·편안함·성능 검증은 별도 후속 항목이며 이번 외관 작업 완료를 막지 않는다. 미검증 상태를 전체 앱의 VR 검증 완료나 제출 승인으로 확대해서는 안 된다.

- **FR-017**: 메뉴와 두 체험은 기존 공용 렌더 설정을 사용해야 한다. 콘텐츠 진입·종료 때 설정을 교체·복원하는 새 컴포넌트나 콘텐츠별 렌더 설정 복사본을 추가하지 않아야 한다. 추가 조명 지원은 기존 공용 설정에서 필요한 항목만 조정하고 메뉴·두 체험의 외관·성능 영향을 함께 검증해야 한다.

### Key Entities

- **콘텐츠별 환경 시안**: 대상 콘텐츠, 공간 연결, 재질·조명·마감 구성과 사용자 승인 상태를 가진 검토 대상.
- **외부 자산 출처 기록**: 사용 자산, 원본 위치, 개별 CC0 근거, 변경 여부와 포함 대상을 연결한 기록.

## Assumptions

### 사용자 확정 사항

- 물건 배치보다 공간 전체의 벽·문·천장·재질·조명이 우선이다. 학교로 한정하지 않고 콘텐츠 상황에 맞는 현실적 환경을 원한다.
- ‘화재 사실 알리기’의 구조 유지, 벽·문 개선, 천장·뒤쪽 마감과 조명·접합부 보완은 합의했다.
- ‘연기 속 대피’의 문 너머 화재, 불꽃 일부·흔들리는 불빛, 문 위쪽 유입·천장 확산은 사용자가 동의했다.
- ‘연기 속 대피’는 현재 방 형태를 유지하며 문틀·천장등·걸레받이와 문 너머 공간을 보완한다. 실제 화면에서 상자 같은 인상 개선 여부를 확인한다.
- 이번 외관 승인은 Unity 실제 실행 화면을 기준으로 한다. 실제 VR 기기 검증은 별도 후속 항목으로 남긴다.
- 연기 요구는 매캐한 색감보다 빽빽함이다. 사용자는 입자 크기를 키워 효과를 봤으나 원래 값으로 되돌렸다. 그 조정이 현재 적용됐다고 간주하지 않는다.

- 조명 구현을 복잡하게 만들지 않는다. 공용 렌더 설정 하나를 사용하고 콘텐츠별 설정 전환 코드는 만들지 않는다.

### 검토 중인 AI 제안 — 채택 전 확정 취급 금지

- 창문, 건물 용도, 정확한 에셋·재질·연기 수치와 화재 규모는 미정이다. 앞서 제안한 휴게 공간과 테이블·선반은 채택되지 않았으므로 포함하지 않는다.
