# 기본 XR 리그 교체

## 승인된 범위

현재 FireNotification 씬의 수제 XR 리그를 설치된 XRI 3.5.1 Starter Assets의
`XR Origin (XR Rig)` 프리팹 기반으로 교체한다. 텔레포트, UI 선택, 비상벨 누르기를 유지한다.
다른 씬과 원본 샘플은 변경하지 않는다.

## 구현 방식

`Assets/_02LWS/Prefabs/XR`에 기본 리그의 프리팹 Variant를 저장한다.
기본 컨트롤러 표현과 추적/레이 설정을 사용하고, 연속 이동·점프·등반·잡아 이동은 끈다.
기존 UI의 누름 유지 방지 처리를 보존하기 위해 InputActionManager에서 기존 UI 입력
에셋도 활성화한다. 별도의 커스텀 입력 활성화 스크립트는 새 리그에 붙이지 않는다.
텔레포트 바닥과 상호작용 매니저를 새 리그에 연결한다.

## 작업과 검증

- [x] 기존 씬과 기본 리그의 참조 및 상호작용 레이어를 확인한다.
- [x] 기본 리그 Variant를 만들고 현재 씬의 리그를 교체한다.
- [x] 프리팹 원본 연결, 입력, 카메라, UI, 비상벨 및 텔레포트 연결을 검증한다.
- [x] Play Mode에서 프레임 진행, UI 선택, 비상벨 누름 및 텔레포트를 확인한다.
- [x] 원래 편집 상태로 복귀하고 변경 및 검증 한계를 기록한다.

## 검증 결과 (2026-11-05)

저장한 씬을 다시 열어 구성 검사 19개를 통과했다. 기본 프리팹의 Variant 연결,
카메라/AudioListener 중복 없음, 양손 Poke/Teleport, 매니저 참조, 텔레포트 레이어,
기존 UI 입력 관리, 기본 컨트롤러 모델, 누락된 스크립트 없음을 확인했다.

Play Mode에서 프레임 진행을 확인하고, 가상 XR HMD/컨트롤러 입력을 통해 동작 검사
17개를 통과했다. 머리/양손 추적, 양손 UI 레이 적중과 트리거 선택, 양손 비상벨
접근/누름, 양손 텔레포트 레이 활성화/바닥 적중/리그 이동을 검증했다.

기존 BellPushInput은 Start에서 활성 오브젝트만 검색하여, 기본 리그가 추적 장치를
기다리며 비활성화한 손끝을 누락했다(캐시 0개). 비활성 손끝도 검색하되 Update의
isActiveAndEnabled 검사를 유지하도록 수정한 후 양손 누름이 통과했다.

컴파일 및 콘솔 오류는 0개였다. XR 오디오 출력의 기본 장치 대체 경고와 가상
컨트롤러의 진동 기능 조회 경고가 있었다. 검증용 장치 제한, 입력 백그라운드 정책,
Editor 백그라운드 실행 강제 설정은 해제하고 Edit Mode로 돌아왔다.

실제 헤드셋을 착용한 레이 방향의 체감, 컨트롤러 모델의 착용 시 위치/크기,
진동 및 헤드셋 오디오는 이번 자동 검증 범위에 포함하지 않는다.

## 제출

Variant는 Samples 폴더의 기본 프리팹과 에셋에 의존한다.
`_02LWS`를 unitypackage로 내보낼 때 Include dependencies를 켜야 하며,
통합 프로젝트에는 호환되는 XR Interaction Toolkit 및 Starter Assets 스크립트 의존성이 필요하다.
